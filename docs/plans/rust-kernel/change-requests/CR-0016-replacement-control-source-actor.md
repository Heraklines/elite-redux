# CR-0016: close replacement control source and actor identity

Status: approved by the integration owner during the M3A-10 independent
re-audit, before the corrected control DTO is merged.

## Problem

The G6 `ReplacementSelectControl` shape carried the global
`FaintOccurrenceId`, field slot, owner seat, and menu, but omitted both the
stored `FaintSource` and the fainted `PokemonId`.

That omission makes two frozen requirements impossible to validate at the
typed plan/projection boundary:

1. a REPLACEMENT `decision_operation_id` contains the authority epoch and the
   per-turn occurrence, while the control carried neither value; and
2. `PartyOptionSelect -> ReplacementSelect` must preserve the same actor, while
   the replacement parent carried no actor.

Appending `/control/...` to an arbitrary non-empty operation string proves only
suffix pinning. It does not prove the exact deterministic decision window.
Deferring both checks to an untyped string or a later renderer would make the
restorable control snapshot internally ambiguous.

## Decision

`ReplacementSelectControl` additionally carries the exact stored faint source
and actor:

```rust
pub struct ReplacementSelectControl {
    pub occurrence: FaintOccurrenceId,
    pub source: FaintSource,
    pub actor: PokemonId,
    pub field_slot: FieldSlot,
    pub owner_seat: SeatId,
    pub menu: BattleMenu,
    pub last_left_option_id: MenuOptionId,
    pub last_right_option_id: MenuOptionId,
}
```

The one `er-game` projector copies `occurrence`, `source`, `actor`, `field_slot`,
and `owner_seat` from the stored `FaintOccurrence`; no field is regenerated by
party scanning. State/projector validation requires that tuple to equal the
stored queue head.

At `BattleControlPlan` and `BattleUiProjection` validation:

- command picker operation IDs are reconstructed from the plan battle, wave,
  turn, player position, and seat and byte-compared;
- replacement picker operation IDs are reconstructed from
  `source.epoch`, plan `battle_id`, `source.wave`, `source.resolved_turn`,
  `source.turn_occurrence`, `field_slot.position`, and `owner_seat` and
  byte-compared;
- `source.wave` and `source.resolved_turn` must equal the plan coordinates;
- replacement remains player-side only; and
- a `PartyOptionSelect` whose parent is `ReplacementSelect` must retain the
  parent's exact actor as well as owner, slot, source-pinned operation,
  selected party slot, and immutable menu history.

The global `occurrence` remains the queue/diagnostic identity. Only
`source.turn_occurrence` supplies the operation ID's `/o` component, preserving
CR-0014's dual-identity decision.

## Compatibility and ownership

This is a pre-production M3 schema correction. No M3 oracle fixture or
production Rust consumer has been published, so the DTO schema remains version
1 and `er-coop-47` is unchanged. Unknown-field rejection still fails closed;
old incomplete replacement-control JSON is intentionally rejected.

The integration owner changes the frozen contracts and freeze assertions. The
M3A-10 owner changes only its two assigned DTO files and tests. Later
`er-game`/state lanes bind the copied tuple to the stored faint occurrence.

## Acceptance evidence

- malformed command and replacement operation prefixes are rejected even when
  their `/control/...` suffix is correct;
- epoch, battle, wave, turn, per-turn occurrence, field, and seat mutations are
  independently rejected;
- global occurrence and per-turn occurrence remain distinct under mutation;
- replacement-parent actor mutation is rejected;
- native and wasm JSON reject a missing `source` or `actor`; and
- the full hosted Rust Kernel Gate is green at the corrected exact SHA.
