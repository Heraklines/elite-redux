## Verdict

**M3A/M3B must not dispatch against the current production boundary.** Spec A requires a real Rust battle path from raw keys through command/move/target/party menus, resolution, Authority V2 material, application, and replacement/outcome [Spec A:L17-L48]. The exact M2 `GameKernel` contains input/UI/scheduler/protocol fields but no game or battle runtime [base@7357166c19bdb5cf0e32c84b0f74f22e79d80798: `rust/crates/er-kernel/src/kernel.rs:111-124`]. The exact base crate tree contains only `er-canonical`, `er-kernel`, `er-protocol`, `er-sim`, `er-testkit`, `er-types`, and `er-wasm`; it contains no `er-rng`, `er-content`, `er-state`, `er-battle`, or `er-game` (`git ls-tree -r --name-only 7357166c19bdb5cf0e32c84b0f74f22e79d80798 -- rust/crates`).

Spec B correctly identifies the risk: M2 still has fixture-authored menus/results, external material/control success boundaries, an untyped snapshot state, and a flat cursor UI [Spec B:L5-L14]. That is an architectural blocker, not a missing helper implementation.

## Proposed contract-freeze decisions

These are recommendations for the central steward, not observed parity facts.

1. **Close the production seam first.** Make the M3 path an internal `RawInput -> InputRouter -> UiReducer -> GameRuntime -> BattleResolver -> AuthorityLog -> material applier -> control installer` chain. Keep `KernelEffect::UiIntent` diagnostic-only if desired, but never let an adapter decide canonical success. Isolate legacy plans in testkit and add the negative architectural checks named by Spec B [Spec B:L26-L83, L1027-L1037].

2. **Use three explicit typed layers.** Freeze (a) canonical game/battle state, (b) typed turn/replacement material with a canonical wire encoding, and (c) a complete restorable kernel/pair snapshot. Keep field IDs and typed IDs in canonical state; do not use the oracle's legacy open JSON blobs as an excuse to leave Rust state untyped [Spec A:L292-L391; Spec B:L231-L358, L1273-L1280].

3. **Make the material applier common to host and guest.** Resolve a candidate, serialize the typed material, apply it on the host through the same production applier, then apply it on the guest. Assert candidate-after == host-applied == guest-applied. Treat the pinned oracle's opaque adapter as compatibility evidence, not as permission to leave the new Rust material opaque [Spec B:L751-L786; oracle@3b534099919efae827019d4a3f3c4ab0ecd6d67b:`src/data/elite-redux/coop/authority-v2/adapters/turn-command.ts:375-407`].

4. **Freeze RNG and arithmetic before damage implementation.** Extract every supported oracle RNG callsite into closed reasons and exact ranges/order. Persist Phaser state as the required exact representation, use JS-compatible `f64` only transiently, and record before/after fingerprints for every draw [Spec A:L395-L462; Spec B:L362-L436]. Do not claim parity from the public battle callsite alone; the internal Phaser state transition remains a gap.

5. **Publish the bounded content and control surface.** Fill the M3 slice manifest with exact IDs, publish capability reason codes, and decide whether the M3 command root is reduced to Fight/Switch or includes the oracle's extra root actions. Reject any reachable unsupported content during initialization and never silently downgrade an ability/effect/status [Spec B:L487-L579].

6. **Freeze menu graph and action order as oracle artifacts.** Add explicit menu edges/instances and the absent action-order document before assigning menu or mechanics implementation. Include command, move, target, party, cancel, hidden/disabled, switch/faint, priority/speed/Trick Room, tie RNG, and trigger ordering [Spec B:L108-L227; Spec A:L688-L728].

7. **Adopt clone-and-swap plus FIFO quiescence.** One external event may produce internal events until the deterministic queue is empty; all canonical work, timer allocation, log preparation, control installation, and validation happen on staged state. A failure discards the staged state and leaks no effect [Spec B:L663-L747].

8. **Separate control, presentation, and protocol retirement.** Install logical control before acknowledging it, keep it non-actionable while blocking presentation is pending, and route presentation failure to recovery/terminal without changing canonical state [Spec B:L843-L884]. This is consistent with the oracle's source-of-truth checkpoint versus presentation-only event split [oracle@3b534099919efae827019d4a3f3c4ab0ecd6d67b:`src/data/elite-redux/coop/coop-transport.ts:1685-1731`].

9. **Freeze identities and digest domains together.** Define one operation grammar, typed proposal fingerprint, duplicate/conflict rule, and local/remote admission symmetry. Then define the three digest shapes and algorithms independently; a mechanical mismatch, protocol/UI mismatch, and presentation-only mismatch must be diagnosable without conflating them [Spec B:L790-L841, L888-L938].

10. **Make the gate honest.** Do not call M3 deployable until the exact M3 manifests, action-order artifact, restorable constructors, error policy, native/Wasm scope, API-bypass negative checks, and zero-resource teardown checks exist. The base M2 gate proves only the current `GameKernel` boundary, not a battle resolver [base@7357166c19bdb5cf0e32c84b0f74f22e79d80798: `rust/crates/er-wasm/src/m2_parity.rs:1-7, 259-315`; Spec A:L1431-L1456].
