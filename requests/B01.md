### R-B01-3  Number-valued form pickers  (PostBattleInitFormChangeAbAttr; the same closure shape is used by PostSummonFormChangeAbAttr, PostTurnFormChangeAbAttr, PostFaintFormChangeAbAttr)

The only constructor argument is `formFunc: (p: Pokemon) => number`, "which form index should I be in?". It is not a
yes/no condition, so `bindCondition` cannot hold it and all 10 users are `legacy-closure` today (reasons written in
`decl/B01/bindings.ts`). Needed: a binding kind for number-valued closures plus these pickers:

- `form.fixed{index}`: `() => index` (Zen Mode, Schooling, Disguise, Ice Face, Zero to Hero, Patchwork = 0; Battle Bond = 1).
- `form.colour-of-current{modulo: 7}`: `p => p.formIndex % 7` (Shields Down).
- `form.step-back{by: 2}`: `p => p.formIndex - 2` (Power Construct; its attr-level condition "form 4 or 5" is carried separately).
- `form.by-hp-line{aboveForm, line: 25%}`: above the HP ratio return the given form, else the base form or the current index
  (Revelation, `init-elite-redux-unown-school.ts:420`; it compares `getHpRatio() > 0.25`, a plain float ratio).

## For the harness owner (B20)

### R-B01-7  `l2StaticReason` must also relax the "attr was evaluated" check

`reachProblems` (harness/twin.ts) only uses `staticReason` to skip the "WHEN unreached" message; it still fails with
"the original never evaluated its attr" when the template cannot reach the class. That makes every class whose WHEN no template
reaches impossible to pass L2 even with a written reason. Three B01 classes hit it today (Rock Head, Sticky Hold, Friend Guard).
Suggested rule: a scenario with a `staticReason` skips `attr-not-evaluated` and still diffs the traces; the owning batch must then
ship its own reaching test (B01 does: `test/tests/elite-redux/decomp/B01/*.test.ts`).

### R-B01-8  Scenario templates (or a per-declaration template override)

Templates that reach the attrs, written and proven in B01's own tests with `twinById`, so they can be moved into `TEMPLATES`:

- recoil: holder (Rock Head) uses Double-Edge on a sturdy foe; WHEN `cancel.indirect-damage`.
- item theft: foe uses Trick on a holder carrying a berry (Knock Off never reaches a player holder); WHEN `cancel.item-theft`.
- allied reduction: doubles, the foe attacks the holder's ally; WHEN `calc.damage-taken` for `AlliedFieldDamageReductionAbAttr`.

  never reaches it (decomp-l2-reach.json lists `event.battle-start` as unreached).
- A Water move cannot be used in the probes of `ReceivedTypeDamageMultiplierAbAttr`: Dry Skin (Fire x1.25) absorbs it before the
  damage calculation, so the class would never be evaluated for that user. B01 drops Water Gun from the shared probe and checks Water in its own test.
- Doubles scenarios need a wave above 1: the opening wild battle is always single (`battle-scene.ts` checkIsDouble), so the
  `doubles-ally` template never produces a double battle with the default start. Suggested: a `wave` field on `ScenarioSpec`
  (and the second player Pokemon needs its own move pick, `game.move.select(move, 1)`, which `afterSelect` can do). B01 ships
  `twinRebuild(..., { wave: 2 })` in `test/tests/elite-redux/decomp/B01/twin-helpers.ts` as a working example; it proves Friend Guard.
