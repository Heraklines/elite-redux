## For the librarian (B19)

### R-B01-1  WHEN `calc.double-battle-chance`  (blocks DoubleBattleChanceAbAttr, which has NO declaration yet)

- `dispatchKey: "DoubleBattleChanceAbAttr"`, kind `calc`, `modifies: "chance"`, `provides: ["holder"]`, group "Move flow" or a
  new group "Wild encounters". Label: "While the game rolls the chance of a double battle".
- Remove `DoubleBattleChanceAbAttr` from `UNEXPOSED_DISPATCH_KEYS` (dispatch-keys.ts:27), it is accounted for by the WHEN.
- Source: `battle-scene.ts:1746` (`applyAbAttrs("DoubleBattleChanceAbAttr", { pokemon: p, chance: doubleChance })` for every
  player Pokemon, `getDoubleBattleChance`), class at `ab-attrs.ts:267` (`apply`: `chance.value /= 4`, no `canApply`, no
  constructor argument, `showAbility` false). The chance is "1 in N", so dividing by 4 makes a double battle four times
  more likely; the result is clamped at 1 afterwards by the caller.
- Needs a harness scenario or an `l2StaticReason` ("wild encounter generation, no moment inside a battle"); the class can
  only be checked by calling `applyAbAttrs` with a `NumberHolder`.
- Users (4 attrs, all attr index 1): Arena Trap (71), No Guard (99), Commander (279), Brawling Wyvern (5307).
- Ready-to-copy declaration for the agent that picks this up once the WHEN exists (Tier C, no params, nothing to bind):

```ts
export default defineDecl(DoubleBattleChanceAbAttr, {
  tier: "C", kind: "calc-modifier", when: "calc.double-battle-chance",
  label: "Make double battles four times as likely",
  summary: () => "Wild encounters are four times more likely to be double battles while I am on the team. Example: 1 in 8 becomes 1 in 2.",
  synonyms: ["more double battles", "double battle chance", "arena trap", "no guard", "wild double encounters"],
  examples: ["Double battles show up four times as often, like Arena Trap"],
  params: [], noParamsReason: "The divide-by-4 is a literal in the class (no constructor argument).",
  conditions: [], guards: [], feasibility: ["The chance can never go below 1 in 1"],
  effect: { id: "effect.package", params: [] },
  reusableAlone: { when: true, if: false, do: true },
  flags: { rng: "none", state: "none", simulated: "respects" },
  probes: [{ name: "a double battle roll", axes: {} }], status: "decomposed", notes: "...",
});
```

### R-B01-3  Number-valued form pickers  (PostBattleInitFormChangeAbAttr; the same closure shape is used by PostSummonFormChangeAbAttr, PostTurnFormChangeAbAttr, PostFaintFormChangeAbAttr)

The only constructor argument is `formFunc: (p: Pokemon) => number`, "which form index should I be in?". It is not a
yes/no condition, so `bindCondition` cannot hold it and all 10 users are `legacy-closure` today (reasons written in
`decl/B01/bindings.ts`). Needed: a binding kind for number-valued closures plus these pickers:

- `form.fixed{index}`: `() => index` (Zen Mode, Schooling, Disguise, Ice Face, Zero to Hero, Patchwork = 0; Battle Bond = 1).
- `form.colour-of-current{modulo: 7}`: `p => p.formIndex % 7` (Shields Down).
- `form.step-back{by: 2}`: `p => p.formIndex - 2` (Power Construct; its attr-level condition "form 4 or 5" is carried separately).
- `form.by-hp-line{aboveForm, line: 25%}`: above the HP ratio return the given form, else the base form or the current index
  (Revelation, `init-elite-redux-unown-school.ts:420`; it compares `getHpRatio() > 0.25`, a plain float ratio).

### R-B01-6  WHEN `calc.ally-damage-taken` and effect `effect.multiply-ally-damage-taken`  (AlliedFieldDamageReductionAbAttr)

- The hook (`pokemon.ts:6367`) calls the ability of every active ally of the Pokemon being hit, with `pokemon` replaced by the
  ally. So in `calc.damage-taken` the frame's `holder` is the Friend Guard owner and the victim is not in the frame; a condition
  such as "holder at full HP" would read the wrong Pokemon. Request a WHEN with `dispatchKey: "AlliedFieldDamageReductionAbAttr"`,

- Effect "Multiply damage my allies take by {multiplier}": `damage.value = toDmgValue(damage.value * multiplier)`. The existing
  `effect.multiply-damage-taken` says "I take". Until then the declaration uses `effect.package`.

## For the harness owner (B20)

### R-B01-7  `l2StaticReason` must also relax the "attr was evaluated" check

`reachProblems` (harness/twin.ts) only uses `staticReason` to skip the "WHEN unreached" message; it still fails with
"the original never evaluated its attr" when the template cannot reach the class. That makes every class whose WHEN no template
reaches impossible to pass L2 even with a written reason. Three B01 classes hit it today (Rock Head, Sticky Hold, Friend Guard).
Suggested rule: a scenario with a `staticReason` skips `attr-not-evaluated` and still diffs the traces; the owning batch must then
ship its own reaching test (B01 does: `test/tests/elite-redux/decomp/B01/*.test.ts`).

### R-B01-8  Scenario templates (or a per-declaration template override)

Templates that reach the attrs, written and proven in B01's own tests with `twinById`, so they can be moved into `TEMPLATES`:

- recoil: holder (Rock Head) uses Double-Edge on a sturdy foe; WHEN `cancel.indirect-damage`.
- item theft: foe uses Trick on a holder carrying a berry (Knock Off never reaches a player holder); WHEN `cancel.item-theft`.
- allied reduction: doubles, the foe attacks the holder's ally; WHEN `calc.damage-taken` for `AlliedFieldDamageReductionAbAttr`.
- battle start: `applyAbAttrs("PostBattleInitAbAttr")` is called from `battle-scene.ts:2684` for the next battle, the `entry` template
  never reaches it (decomp-l2-reach.json lists `event.battle-start` as unreached).
- A Water move cannot be used in the probes of `ReceivedTypeDamageMultiplierAbAttr`: Dry Skin (Fire x1.25) absorbs it before the
  damage calculation, so the class would never be evaluated for that user. B01 drops Water Gun from the shared probe and checks Water in its own test.
- Doubles scenarios need a wave above 1: the opening wild battle is always single (`battle-scene.ts` checkIsDouble), so the
  `doubles-ally` template never produces a double battle with the default start. Suggested: a `wave` field on `ScenarioSpec`
  (and the second player Pokemon needs its own move pick, `game.move.select(move, 1)`, which `afterSelect` can do). B01 ships
  `twinRebuild(..., { wave: 2 })` in `test/tests/elite-redux/decomp/B01/twin-helpers.ts` as a working example; it proves Friend Guard.

### R-B01-10  Atom `move.has-built-in-flag{flag}`  (MoveImmunityAbAttr, 6 users)

- Formula `move.hasFlag(MoveFlags[flag])`, source `move.ts:475`. It reads the move's own flag bit and does NOT ask the
  user's abilities. The existing `move.flag` calls `doesFlagEffectApply`, which also returns true for a flag that an
  ability injects (`MoveFlagInjectionAbAttr`, the ER Rapier injector), so it is not the same predicate.
- Users (all bound as legacy-closure today): Shield Dust (19 attr 1), Overcoat (142 attr 1), Powder Burst (5243 attr 1),
  Guardian Coat (5539 attr 2) with POWDER_MOVE; Bulletproof (171 attr 0), Chestnut Shield (5657 attr 1) with BALLBOMB_MOVE.
  Each closure is `(pokemon, attacker, move) => pokemon !== attacker && move.hasFlag(F)`, so the binding becomes
  `all[ not side.is{self}, move.has-built-in-flag{F} ]`.
- A cheaper alternative the librarian may prefer: a boolean `includeInjected` param on `move.flag`, default true.

### R-B01-11  Atom `move.targets-whole-side`  (MoveImmunityAbAttr user Good as Gold; also the first clause of the TypeImmunity family)

- Formula `[MoveTarget.BOTH_SIDES, MoveTarget.ENEMY_SIDE, MoveTarget.USER_SIDE].includes(move.moveTarget)`, source
  `ab-attrs.ts` `TypeImmunityAbAttr.canApply` clause 1 and the Good as Gold closure (`init-elite-redux...` Good as Gold,

- Good as Gold becomes `all[ not side.is{self}, move.category{STATUS}, not move.targets-whole-side ]`.

### R-B01-12  Atoms `mon.is-first-ally{who}` and `move.is-attack-move`  (MoveImmunityAbAttr user Telepathy)

### R-B01-14  Slot `typeMultiplier` plus atom `matchup.compare{cmp, n}` for `calc.move-immunity`  (NonSuperEffectiveImmunityAbAttr gate)
