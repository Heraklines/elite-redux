# Requests from batch B05 (chunks 1 and 2 of 4) to the librarian (B19), the harness owner (B20) and the foundation owner

Not code. One entry per request: id, what it must do, the source line, and which class needs it. Chunk 1 owns these
classes: DrenchImmunityAbAttr, StealthRockImmunityAbAttr, DoubleSelfInflictedDamageAbAttr, SuppressFieldEffectsAbAttr,
OverruleCritAbAttr, SuppressFieldAbilitiesWhenEnragedAbAttr, SpreadTargetByFlagAbAttr, SetMoveAccuracyAbAttr.

Seven of the eight classes are presence flags: the class body is empty and the behaviour sits in engine code that calls
`hasAbilityWithAttr(...)`. They are declared `while-active` (precedent IgnoreContactAbAttr) and every one of them is
exercised AT its engine site in `test/tests/elite-redux/decomp/B05/flag-sites.test.ts` (original, rebuilt, and a control
without the flag). Splitting them into WHEN / IF / DO blocks needs the engine to read the behaviour through a dispatched
hook, which no class agent may do. The entries R-B05-2 to R-B05-8 below say exactly which hook, atom and effect each
class needs once the foundation owner opens those sites.

## For the librarian (B19)

### R-B05-1  Effect `effect.raise-base-accuracy`  (SetMoveAccuracyAbAttr; the only Tier B class of the chunk)

- Calc effect on WHEN `calc.accuracy` (`modifies: "accuracy"`, `requires: []`), param `accuracy` (slider 1 to 100, integer,
  default 90, label "Base accuracy (%)").
- Formula: `if (accuracy.value !== -1 && accuracy.value < N) accuracy.value = N`. Source `ab-attrs.ts`
  `SetMoveAccuracyAbAttr.residual` and `.apply`. The `-1` guard (never-miss moves are left alone) and "only ever raises"
  are part of the effect, not of the IF list. It runs BEFORE the evasion / accuracy stages (`Move.calculateBattleAccuracy`,
  `move.ts:1249`), so stages still count on top; this is why `effect.always-hit` is not a substitute (it skips evasion).
- Until it exists the declaration uses `effect.package` with the typed param `accuracy`; the trigger, the move gate and the
  number are already separate blocks. Please swap the declaration's `effect` to the new id when it lands.
- Users (3 attrs): Hypnotist (5065, attr 0, Hypnosis 90), Lunar Eclipse (5103, attr 2, Hypnosis 90), Lullaby (5487, attr 0, Sing 90).
- Related, other batches: SleepingInAccuracyAbAttr (sets 100 for sleep-inducing moves), SetlistAccuracyAbAttr and
  FanFavoriteAccuracyAbAttr (multiply the accuracy) extend the same class but override canApply and apply.

### R-B05-2  Tag immunity for the Drenched effect  (DrenchImmunityAbAttr)

- The flag is read only in `ErDrenchedTag.canAdd` (`battler-tags.ts:4550`, `pokemon.hasAbilityWithAttr("DrenchImmunityAbAttr")`).
  Needs: the engine routes `ER_DRENCHED` through the same tag-immunity hook as the other tags (`BattlerTagImmunityAbAttr`,
  `effect.negate` with a `tag` param). Then "cannot be drenched" is the existing block with tag Drenched and this class can
  retire. B19: please make sure `ER_DRENCHED` is a choice of the tag lists with a player-facing name "Drenched".
- Users (3 attrs): Amphibious (5035, attr 1), Old Mariner (5324, attr 3), Poseidon's Dominion (5485, attr 1).

### R-B05-3  While-active effect blocks for "field effects off"  (SuppressFieldEffectsAbAttr)

- Needs an effect `effect.switch-off-field-effects` (while-active, params: terrain, rooms, gravity as three booleans, default
  all true) reading the same `Arena.isFieldEffectSuppressed()` (`arena.ts:230`) that the terrain getter, the Room hooks and
  `Arena.hasActiveGravity()` already call. The class today is the flag; the effect block would own it.
- User: Clueless (5162, attr 1). It has a second attr for weather (a separate class).

### R-B05-4  Critical-hit atom and two calc effects  (OverruleCritAbAttr)

- Atom `move.is-critical` (requires a new frame slot `crit`, true when the hit being calculated is a critical hit). Source:
  the `isCritical` argument of `Pokemon.getAttackDamage` (`pokemon.ts:6269` and `:6354`).
- Effect `effect.skip-damage-cut-abilities` (calc effect on WHEN `calc.damage-dealt`): the defender's
  `ReceivedMoveDamageMultiplierAbAttr` and the allies' `AlliedFieldDamageReductionAbAttr` are skipped (`pokemon.ts:6354` to `6370`).
- The doubling needs no new effect: `effect.multiply-damage-dealt` x2 with the existing `move.effectiveness` atom (below 1)
  and the new crit atom. Both sites also test `!ignoreSourceAbility`.
- Engine requirement: the two sites must dispatch a hook instead of calling `hasAbilityWithAttr("OverruleCritAbAttr")`.
- Users (2 attrs): Overrule (5516, attr 0), Magistrate (6010, attr 1).

### R-B05-5  A while-active flag that can carry an IF  (SuppressFieldAbilitiesWhenEnragedAbAttr)

- The rule is "while I have the enrage tag, every other on-field Pokemon's suppressable ability is off". The IF already exists
  (`tag.has` with `ER_ENRAGE`), the DO does not: effect `effect.switch-off-other-abilities` (while-active). What is missing is
  an IF slot on `while-active` blocks: the engine check `Pokemon.canApplyAbility` (`pokemon.ts:3835`) would read the compiled
  IF through `isActiveFor` (the hook `abilityStudioRuntimeComponentIsActive` already honours) instead of testing the tag itself.
- User: Mental Pollution (5517, attr 0). It has no attr that enrages itself, so today it only works when something else
  enrages the holder.

### R-B05-6  Target-selection WHEN and effect  (SpreadTargetByFlagAbAttr)

- WHEN `calc.move-targets` ("While the game picks the targets of my move", provides holder and move) dispatched from
  `getMoveTargets` (`move-utils.ts:88`), and an effect `effect.hit-both-foes` (promote NEAR_OTHER and NEAR_ENEMY to
  ALL_NEAR_ENEMIES, never for multi-hit moves). The IF is the existing `move.flag`, but note the class uses the plain
  `move.hasFlag(flag)`, not `doesFlagEffectApply`: B19 please provide an atom variant (or a param) with `hasFlag` semantics.
- Today the property is the class's own param `flag`, so a staff block "hit both foes" already works with any of the 23
  properties and needs no binding.
- Users (8 attrs, flag in brackets): Artillery (5114, attr 1, pulse), Super Scope (5478, attr 2, pulse), Amplifier (5115,
  attr 1, sound), Bass Boosted (5253, attr 1, sound), Wind Chimes (5720, attr 1, sound), Siren's Song (20015, attr 4, sound),
  Sweeping Edge (5157, attr 1, slicing), Blademaster (5297, attr 1, slicing).

### R-B05-7  Self-damage and entry-hazard hooks  (DoubleSelfInflictedDamageAbAttr, StealthRockImmunityAbAttr)

- DoubleSelfInflictedDamageAbAttr: WHEN `calc.self-inflicted-damage` ("While a foe hurts itself from confusion or enrage"),
  dispatched on the foes of the self-hurting Pokemon from `ConfusedTag.lapse` (`battler-tags.ts:1129`) and
  `ErEnrageTag.lapse` (`:4608`); effect `effect.multiply-damage-taken` x2 already exists.
- StealthRockImmunityAbAttr: WHEN `calc.entry-hazard-damage` ("While an entry hazard would hurt me"), dispatched from
  `StealthRockTag.activateTrap` (`arena-tag.ts:1115`), with a hazard choice, and the effects `effect.negate` plus
  `effect.heal-percent` 25 (when not at full HP). Both exist; only the hook and the hazard param are missing.
- Users: Cosmic Daze (5263, attr 1), Cosmic Dust (5640, attr 2); Mountaineer (5052, attr 1), Ice Plumes (5571, attr 3),
  Free Climb (5962, attr 4).

# Requests from batch B05 (chunk 2 of 4)

## For the librarian (B19)

### R-B05-9  Effect `effect.raise-crit-stage`  (BonusCritAbAttr)

- Calc effect on WHEN `calc.crit-stage` (`modifies: "critStage"`, `requires: []`), param `stages` (slider 1 to 3, integer,
  default 1, label "Critical hit levels to add"). Formula `critStage.value += stages`. Source `ab-attrs.ts`
  `BonusCritAbAttr.apply`; the engine reads the level in `Pokemon.getCritStage` (`pokemon.ts:2063`) and picks the odds from
  `[24, 8, 2, 1][clamp(stage, 0, 3)]` (`pokemon.ts:6437`). `effect.force-crit` is "always", not a level, so it is no substitute.
- Until it exists the declaration uses `effect.package` with no param (the +1 is a literal in the class and the constructor
  takes nothing). Please swap the declaration's `effect` to the new id when it lands.
- User: Super Luck (105, attr 0). Related, other batch: CritStageBonusAbAttr (archetype) extends the class.

### R-B05-10  Effect `effect.multiply-crit-damage`  (MultCritAbAttr)

- Calc effect on WHEN `calc.crit-multiplier` (`modifies: "critMultiplier"`, `requires: []`), param `multiplier` (slider 1 to 4,
  step 0.05, default 1.5, label "Extra critical hit damage (1.5 = crits hit 50% harder)").
- Formula: `if (critMult.value > 1) critMult.value *= multiplier`. The `> 1` test is part of the effect: the engine starts a
  plain hit at 1 and a critical hit at 1.5 (`pokemon.getAttackDamage`, `pokemon.ts:6069`), so only critical hits are changed.
  Source `ab-attrs.ts` `MultCritAbAttr.canApply` and `.apply`. The hook is asked for the ATTACKER and only while the attacker's
  ability is not ignored.
- Until it exists the declaration uses `effect.package` with the typed param `multiplier`.
- Users (4 attrs, all 1.5): Sniper (97, attr 0), Super Sniper (5507, attr 0), Fourth Degree (6107, attr 0), Kagutsuchi (6109, attr 2).

### R-B05-11  Effect and WHEN for the turn order inside a priority bracket  (ChangeMovePriorityInBracketAbAttr)

- Effect `effect.set-turn-order-place`: SETS (does not add) the place among moves of equal priority, param `position`
  (select First, Normal, Last; default Last). Formula `priority.value = position` with `LAST = 0, NORMAL = 1, FIRST = 2`
  (`MovePriorityInBracket`). `effect.change-priority` ADDS a number, so it cannot express this.
- WHEN `calc.priority-bracket` ("While the game orders moves of equal priority"): the class is dispatched from
  `Move.getPriorityModifier` (`move.ts:1455`), a different call from `Move.getPriority` (`move.ts:1445`) that `calc.priority`
  stands for. Today the declaration uses `calc.priority`, which lists the class as an also-dispatched key. The engine afterwards
  forces LAST for a drenched holder unless FIRST was set (`move.ts:1461`): that stays in the engine.
- User: Mycelium Might (298, attr 0, status moves, Last).

### R-B05-12  HP atoms that read the rounded ratio, and the foe list  (ConditionalCritAbAttr, ChangeMovePriorityAbAttr)

- Atom `hp.ratio-compare{who, cmp, pct}` with `who` = holder / other / ally / **any foe** (true when ANY opponent matches), whose
  formula is `Math.round(hp / maxHp * 100) / 100` compared with `pct / 100` (that is `Pokemon.getHpRatio()` without the
  `precise` flag, `pokemon.ts:2432`). It is NOT the same as `hp.at-most` / `hp.at-least`, which compare exact integers
  (`hp * 100 <= maxHp * pct`): the rounded ratio is below 0.5 for every HP below 49.5%, not 50%.
- Users: Ape Shift (5436, attr 1): holder, `getHpRatio() < .5`. Opportunist (290, attr 0, `ChangeMovePriorityAbAttr`): any
  opponent, `getHpRatio() <= .5`, wrapped in a try/catch that answers false on any error.
- Both are `bindLegacyClosure` today, so they count as undecomposed until the atom exists.

### R-B05-13  `move.is-move` must accept Elite Redux move names  (ChangeMovePriorityAbAttr)

- `move.is-move` reads `MoveId[moveId]`; Elite Redux moves live in `ErMoveId` (`src/enums/er-move-id.ts`, for example
  `FIVE_STAR_FURY: 5156`), so the atom cannot name them. Please make the param accept both enums (the choice list should show the
  player-facing move name).
- User: Penta-Punch (6015, attr 2): `move.id === ErMoveId.FIVE_STAR_FURY`, `bindLegacyClosure` today.

### R-B05-14  A WHEN of its own for damage from a status condition  (BlockStatusDamageAbAttr)

- WHEN `cancel.status-damage` ("While the game checks if my status condition hurts me"), dispatch key `BlockStatusDamageAbAttr`,
  provides `holder`. It is dispatched only from the status tick (`post-turn-status-effect-phase.ts:35`, right after
  `BlockNonDirectDamageAbAttr`, with the SAME `cancelled` holder). Today `cancel.indirect-damage` lists it as an also-dispatched
  key "at the same moment with the same parameter shape", which is only true for that one site: indirect damage from weather,
  hazards, recoil and so on never asks BlockStatusDamageAbAttr.
- The IF is `status.has` (exists), the DO `effect.negate` (exists). The declaration keeps `cancel.indirect-damage` until then.
- Users (6 attrs): Marvel Scale (63, attr 1), Poison Heal (90, attr 1), Toxic Boost (137, attr 1), Flare Boost (138, attr 1),
  Rainbow Fish (5943, attr 2), Decay (6051, attr 2).

### R-B05-15  Engine-query routing for "indirect damage is blocked"  (BlockNonDirectDamageAbAttr; foundation owner and B19)

- Besides the dispatched checks, six places only PEEK at the class with `hasAbilityWithAttr("BlockNonDirectDamageAbAttr")` or by
  constructor name: `ab-attrs.ts:1274`, `:5209`, `:5670`, `archetypes/contact-damage-on-hit.ts:157`,
  `init-elite-redux-vanilla-rebalance.ts:2469`, `er-tactical-items.ts:858`. A rebuilt attr keeps its class name, so those still work,
  but an ability built only from library pieces (`cancel.indirect-damage` + `effect.negate`) would be invisible to them.
  Please route them through one `abilityQuery(pokemon, "blocks-indirect-damage")` (an engine-query, like FloatAbAttr) that also
  counts a composed block.
- Users (10 attrs): Magic Guard (98), Impenetrable (5064), Apple Enlightenment (5317, attr 1), Conjurer Of Deceit (5464),
  Immovable Object (5490, attr 0), Cosmic Dust (5640), Chestnut Shield (5657), Titan (5934), Old Ocean Relic (20009),
  Mystic Fortification (20014).

### R-B05-16  Atom "the hit is a critical hit" for MultCritAbAttr

- Same atom as R-B05-4 (`move.is-critical`, frame slot `crit`). It would let `MultCritAbAttr`'s `critMult > 1` test become an IF

## For the harness owner (B20)

### R-B05-17  Shared harness edits made by this chunk (please keep)

- `harness/world.ts`, `PARAM_BUILDERS`: builders for `calc.priority`, `calc.crit-stage`, `calc.crit-multiplier`, `calc.crit-roll`,
  `cancel.indirect-damage` and `cancel.one-hit-ko`, each exactly the object the engine passes (see the comments there). Needed by
  the Tier B attr differential (the priority and status-damage gates) and useful for the other classes of those WHENs.
- `harness/scenarios.ts`: two new templates and two re-mapped WHENs, because the old templates never reached the trigger:
  `calc.crit-multiplier` was mapped to `foe-crits-holder` (the hook is asked for the ATTACKER, so it needs the new
  `holder-crits-foe`), `cancel.indirect-damage` was mapped to `weather-set` (nothing there hurts the holder, so it needs the new

  fixture `decomp-l2-reach.json` was regenerated (two WHENs moved from `unreached` to `reached`, nothing else; the file keeps its 2-space format).
- `harness/l2-twin.test.ts`: `ClassDecl.l2StaticReason` was documented as the way for a class whose WHEN no template reaches to
  pass L2, but only the "WHEN is unreached" message honoured it, not "the original never evaluated the attr". It now also skips the
  evaluated-attr requirement when the declaration has an `l2StaticReason` AND the WHEN is listed in `unreached`. Needed for
  BlockOneHitKOAbAttr (`cancel.one-hit-ko`): no move of the game has OneHitKOAttr any more (see the notes of that declaration).
- The shared L1 grid only varies the HOLDER. Foe-side facts (status, bleeding, Speed stage) and the turn counter are never varied,
  so Merciless, Depravity, Relentless and the first-turn crits are proven in `test/tests/elite-redux/decomp/B05/chunk2-sites.test.ts`.
  A foe-state axis (`foeStatus`, `foeStage`, `turn`) would let L1 and L2 see them for everybody.
