## For the librarian (B19)

### R-B06-1  A heal effect that takes a fraction and a rounding  (PostTurnStatusHealAbAttr)

- The class heals `toDmgValue(pokemon.getMaxHp() / 8)` (floor, at least 1) in `apply` (`ab-attrs.ts`, PostTurnStatusHealAbAttr.apply).
  `effect.heal-percent` is the nearest block, but its percent slider is `integer: true`, so 12.5 does not fit, and its rounding is not the
  same. Either allow a non-integer percent with the `toDmgValue` rounding, or add `effect.heal-fraction` with params `denominator` (integer,
  default 8, range 1 to 64) and the message choice.
- The class has no constructor argument for the 1/8, so it is not a typed setting today. Making it one needs a constructor change
  (a trailing optional argument would keep every caller working), which class agents may not do: this is a foundation decision. The same
  request exists for the sibling class PostTurnHealAbAttr (1/16, another chunk).
- Used by: Poison Heal (90, attr 0).

### R-B06-2  Stat choice "a random stat" with "not the one just raised", and the literals as settings  (MoodyAbAttr, SpeedBoostAbAttr)

- `effect.stat-stage` takes one named stat and a fixed number of stages. Moody needs: raise a RANDOM stat by `up` stages (default 2), then
  lower a DIFFERENT random stat by `down` stages (default 1). Stats at +6 (for raising) and -6 (for lowering) are left out of the choice, and a
  stat already raised is left out of the lowering choice. Draws: `randBattleSeedInt(canRaise.length)` first (only when canRaise is not empty),
  then `randBattleSeedInt(canLower.length)` (only when canLower is not empty), source `ab-attrs.ts` MoodyAbAttr.apply. Suggested: a `stat`
  option `RANDOM` plus a boolean `not the stat just changed`, or a new `effect.random-stat-swing` with the two amounts.
- Until then Moody is a package. Its two amounts and SpeedBoostAbAttr's `+1 Speed` are literals in `apply`; to make them typed settings the
  classes need optional trailing constructor arguments (the existing calls pass none, so they keep working). That is a foundation decision.
- Used by: Moody (141, attr 0); Speed Boost (3, attr 0) and Max Acceleration (5379, attr 0) for the literal +1 Speed.

### R-B06-3  (convenience, optional) Atom "I have any status problem"  (PostTurnResetStatusAbAttr)

- The class tests `(!!status && status !== FAINT) || hasErAilment(pokemon)` with `ER_AILMENT_TAGS` = Bleed, Frostbite, Fear (`er-status-cure.ts`).
  The binding spells it as `any[ status.has ANY, tag.has ER_BLEED, tag.has ER_FROSTBITE, tag.has ER_FEAR ]`, which is correct but long for staff.
  A single atom `status.any-problem` ("{who} has a status or an ailment such as Bleed, Frostbite or Fear") would read better and stay correct when
  a fourth ER ailment is added. `status.has` ANY would also have to leave out FAINT (the class does; the bound tree does not, which cannot be seen in a
  real battle, see the test `PostTurnResetStatusAbAttr ... FAINT`).
- Used by: Shed Skin, Hydration, Leaf Guard, Healer, Big Leaves, Purifying Waters, Pattern Change, Caretaker, Sun's Bounty, Wonder Scale (12 attrs).
- Also: "ally next to me" as a `who` value (`getAdjacentAllies()`, triple battles) would let the ally pick be an IF; today the pick stays in the class.

### R-B06-4  Chance atom with a float roll and a number-valued chance  (PostTurnRestoreBerryAbAttr)

- `rng.chance` is `randBattleSeedInt(100) < pct`. The class rolls `pass = randSeedFloat()` and tests `procChance(pokemon) >= pass` (source
  `ab-attrs.ts` PostTurnRestoreBerryAbAttr.canApply), which uses the global stream and a different compare, so the library atom would change the
  random numbers drawn. Needed: `rng.chance-float` with `pct` (1 to 100) that draws `randSeedFloat()` ONCE, always (even at 100), and passes when
  `pct / 100 >= draw`. For the users the chance depends on the weather: `any`/`if` over `field.weather` cannot express "100% in the sun, 50%
  otherwise" as ONE roll, so either the atom takes a second `pctIf` and a condition, or the class gets two chance slots.
- Also needed on the same class: the berry ledger test "I ate a berry this battle that I can still get back" (`battleData.berriesEaten` minus the
  berries whose held stack is at its cap) as an atom `item.berry-restorable`. Today it stays in the class as feasibility, checked BEFORE the draw.
- Used by: Harvest (139, attr 0), Big Leaves (5111, attr 3), Sun's Bounty (5502, attr 1), Glycolysis (5970, attr 0), Serfdom (6055, attr 0).
  Serfdom's chance function is `isReapAndSowSunActive(pokemon) ? 1 : 0.5` (Grassy terrain and a Reap and Sow holder on the field).

### R-B06-5  Effect `effect.restore-eaten-berry`  (PostTurnRestoreBerryAbAttr)

- "Get back one berry I ate in this battle": picks `randSeedInt(berriesUnderCap.length)`, removes it from `battleData.berriesEaten`, adds one to the
  matching BerryModifier stack (or creates one for the player or the enemy side), updates the modifier bar and queues the message
  `abilityTriggers:postTurnLootCreateEatenBerry`. Source `ab-attrs.ts` PostTurnRestoreBerryAbAttr.createEatenBerry. No settings.
- Used by: the five Harvest-style attrs above. The class stays the single source of the behaviour; the effect only names it.

### R-B06-6  Effects `effect.remember-eaten-berries` and `effect.eat-remembered-berries`  (CudChewRecordBerryAbAttr, CudChewConsumeBerryAbAttr)

- remember: `pokemon.summonData.berriesEatenLast = pokemon.turnData.berriesEaten` at the end of the turn (a bookkeeping effect, ignores
  `simulated`, stores the same array).
- eat: for each berry in `summonData.berriesEatenLast`, play `CommonAnim.USE_ITEM` once and run `getBerryEffectFunc(berry)(pokemon)` and fire a
  `BerryUsedEvent`. Nothing is consumed and it does not count as eating (Unnerve, Stuff Cheeks and Unburden do not see it).
  `effect.use-item` is not a substitute (it eats the HELD item and consumes it).
- Used by: Cud Chew (291, attrs 0 and 1) only. Both are packages today, each with a written reason in its declaration.

### R-B06-7  Two atoms for "did not just arrive"  (SpeedBoostAbAttr)

- `time.switched-in-this-turn`: "{who} switched in this turn", formula `pokemon.turnData.switchedInThisTurn`.
- `time.failed-run-away`: "{who} failed to run away this turn", formula `pokemon.turnData.failedRunAway`.
- The class's gate is `simulated || (!switchedInThisTurn && !failedRunAway)` (`ab-attrs.ts` SpeedBoostAbAttr.gate). With the two atoms the binding is
  `all[ not switched-in-this-turn, not failed-run-away ]`; the `simulated ||` part is only a pass-through for previews (no engine path asks for
  one at turn end). Do not confuse `switched-in-this-turn` with `time.first-turn` (`waveTurnCount <= 1`): the first differs on a switch-in after a
  faint, the second is a turn counter.
- Used by: Speed Boost (3, attr 0), Max Acceleration (5379, attr 0). Another user of `turnData.switchedInThisTurn` is the Stakeout closure (other chunk).

### R-B06-8  Number-valued form pickers and the atoms their users need  (PostTurnFormChangeAbAttr)

- The class's one argument is `formFunc(pokemon): number` ("which form index should I have?"). The library has only yes/no atoms. Needed (same
  shape as B01's R-B01-3): either a form-picker block, or the yes/no atoms that let a staff rule say what the functions say:
  `mon.form-index {who, cmp, n}` (`pokemon.formIndex`), `mon.level {who, cmp, n}` (`pokemon.level`), a ratio test `hp.ratio {who, cmp, ratio}`
  for `getHpRatio() <= r` (`hp.at-most` exact with a whole percent is the same value, see PRECEDENTS.md section 5, but 0.25 and 0.5 are the only ratios used),
  and `mon.form-key-empty {who}` (`getFormKey()` is empty).
- Functions to cover: Zen Mode `hpRatio <= 0.5 ? 1 : 0`; Shields Down `formIndex >= 7 ? formIndex : formIndex % 7 + (hpRatio <= 0.5 ? 7 : 0)`;

  Hunger Switch and Two-Faced `getFormKey() ? 0 : 1` and `getFormKey() ? 1 : 0`; Revelation `hpRatio > 0.25 ? revelationIndex : (formIndex === revelationIndex ? 0 : formIndex)`.

  or `effect.run-ability-form-change`); this batch declares `effect.change-form` until it exists and the librarian should repoint it. The class is
  also in `Pokemon.FORM_CHANGE_DRIVER_ATTRS` (`pokemon.ts:3579`) by class name; the class name must not change.
- Used by: Zen Mode (161, attr 2), Shields Down (197, attr 2), Schooling (208, attr 2), Power Construct (211, attr 2), Hunger Switch (258, attrs 0 and 1),
  Two-Faced (5486, attrs 0 and 1), Revelation (5586, attr 2).

## For the harness owner (B20)

### R-B06-H1  The stock L1 differential reports noise for an attr-level condition that draws from the global random stream

- `harness/differential.ts` `runAttrDifferential` compares `attr.getCondition()` of the original and of the rebuild, but pins only
  `game.scene.randBattleSeedInt` (`RngProbe`). Shed Skin (61), Pattern Change (5371) and Wonder Scale (5528) carry the attr-level condition
  `randSeedInt(100) < 30` (`init-elite-redux-vanilla-rebalance.ts:1268`, `Phaser.Math.RND.integerInRange`), so the two sides roll different numbers and
  `harness/l1.test.ts` fails with "getCondition is false for the original but true for the rebuild" for exactly these three abilities. It is not a
  behaviour difference (the rebuild carries the SAME closure object).
- Fix suggestion: in `RngProbe.reset()` also re-seed the global stream (`Phaser.Math.RND.sow(["l1"])`) before each side, or skip the `getCondition`
  comparison when `attr.extraCondition` is the same function on both sides.
- Until then `test/tests/elite-redux/decomp/B06/l1-seeded.test.ts` runs the same differential for this chunk's classes with the 0..99 roll pinned to a
  passing and then a failing value, and passes.
- The L2 twin passed for these abilities because the attr-level condition is the same object and L2 compares whole battles.

## For the foundation owner

### R-B06-F1  A Tier B gate that is evaluated on a different Pokemon than the holder  (PostTurnResetStatusAbAttr)

- Ally mode (`new PostTurnResetStatusAbAttr(true)`: Healer attr 0, Caretaker attr 0) cures the first adjacent ally with a status. The class picks that
  ally in `guards` and `prepare` hands it to the gate as the frame's `pokemon`, so a library IF such as "HP at most 50%" reads the ally, not the holder.
  This is a pure move of the original code (the pick was the first thing the old `canApply` did) and the L1 grid and the B06 test prove the
  rebuild equals the original, but it is a convention the editor should show: for this block the IF talks about "the Pokemon that would be cured".
  If you prefer the IF to always talk about the holder, the pick must become an `ally` slot of `event.end-of-turn` instead.
