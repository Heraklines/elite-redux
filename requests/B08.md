# Library requests from batch B08 (chunk 1 of 5) to the librarian (B19)

Not code. Chunk 1 owns these eight classes (all in `src/data/elite-redux/archetypes/`): AbsorbantAbAttr,
AddTypeToAttackerOnContactAbAttr, AllyAttackPowerBoostAbAttr, AteConditionalStatusAbAttr, AttackStatSubstituteAbAttr,
BoneMoveTypeChartAbAttr, ChanceDodgeAbAttr, ChanceStatusOnHitAbAttr. Later chunks of B08 append their own requests;
ids of this chunk are R-B08-1 to R-B08-10.

Review round 2: the blocking findings could not wait for the librarian, so the atoms, WHENs and the harness fix that
blocked chunk 1 were added in this branch (as batches B01, B04 and B06 did). They are listed here as DONE so B19 can
review them instead of writing them again; a merge conflict in the vocabulary files resolves by keeping both sides and
regenerating the catalog (`ER_WRITE_CATALOG=1 npx vitest run test/tests/elite-redux/tools/dump-catalog.test.ts`).

Declared and live (`decl/B08/`): AbsorbantAbAttr (Tier B, Leech Seed half split into WHEN + IF + DO), AddTypeToAttackerOnContactAbAttr
(Tier B), AllyAttackPowerBoostAbAttr (Tier C), AteConditionalStatusAbAttr (Tier B, branches), AttackStatSubstituteAbAttr (Tier C),
BoneMoveTypeChartAbAttr (Tier C), ChanceStatusOnHitAbAttr (Tier B, all 10 gates bound). ChanceDodgeAbAttr is declared with
status `exempt` until the owner decides about its missing dispatch (R-B08-10b).

## R-B08-1  Atom `move.inherent-flag`  DONE in this branch

- `vocabulary/conditions.ts` + `evaluate/conditions.ts`: `move.hasFlag(MoveFlags[flag])`, NOT `move.flag` (which is user-aware: Long Reach
  and substitutes). Used by the four non-contact-tier gates of ChanceStatusOnHitAbAttr (Static 9, Flame Body 49, White Noise 5358,
  Smoldering Wood 5733), now bound in `decl/B08/bindings.ts`. Test: `test/.../B08/new-atoms.test.ts`.

## R-B08-2  Atom `hit.landed-damage`  DONE in this branch

- Evaluates the class's own `DAMAGING_HIT_RESULTS` (now exported from `archetypes/chance-status-on-hit.ts`, so there is one set).
  The four gates become `all[ not(move.inherent-flag MAKES_CONTACT), hit.landed-damage, status.has other NONE, rng.chance pct ]`.

## R-B08-3  Atom `move.drains`  DONE in this branch

- `move.hasAttr("HitHealAttr")`. With `mon.protected-from-effects` (new, Shield Dust test: `hasAbilityWithAttr("IgnoreMoveEffectsAbAttr")`)
  the Leech Seed half of AbsorbantAbAttr is now a Tier B gate `all[ move.drains, not(mon.protected-from-effects other) ]`; the class
  `canApply` is `gate && residual` (`canAddTag(SEEDED)` stays in the class).

## R-B08-4  Effect `effect.add-type`  (AddTypeToAttackerOnContactAbAttr)  still open

- Event effect on WHEN `event.after-hit`, label "Give {target} an extra {type} type", params `target` (who) and `type`. `requires: ["other"]`.
- Formula (`archetypes/add-type-to-attacker-on-contact.ts`, `apply`): unless simulated, `target.summonData.addedType = type`,
  `target.updateInfo()`, then queue the `moveTriggers:addType` message with the type name and `getPokemonNameWithAffix(target)`.
  Feasibility that stays with the effect: the target is not Terastallized and does not already have the type.
- Same mechanism as Forest's Curse / Trick-or-Treat. Until it exists the declaration uses `effect.package` for the DO part only; the
  WHEN and the IF (contact) are already real blocks.
- Synonyms to carry: extra type, add a type, forest's curse, woodland curse, infect type.

## R-B08-5  Atom `move.targets-one-pokemon` (or an exact `kind` for `move.target-kind`)  (ChanceDodgeAbAttr, optional)

- The class' own set `SINGLE_TARGET_KINDS` is { NEAR_OTHER, OTHER, NEAR_ENEMY, ENEMY_SIDE }. The library's `move.target-kind` "single" is
  { OTHER, NEAR_OTHER, RANDOM_NEAR_ENEMY }: they differ. So the class' setting `singleTargetOnly` cannot be an IF yet and stays a boolean param.
- Only worth doing together with R-B08-10b.

## R-B08-6  Guards `hit-connected-on-another-pokemon` and `blocked-by-effect-shield`  (AteConditionalStatusAbAttr)  still open

## R-B08-7  WHEN `calc.attack-stat`  DONE in this branch

- `vocabulary/when-registry.ts`: kind calc, dispatch key `AttackStatSubstituteAbAttr`, `WHEN_MOVE_USER` holder. The engine does not dispatch
  it with `applyAbAttrs` (`Pokemon.getBaseDamage` scans for a `resolveStat` function). Template `holder-hits-foe` is mapped

- Other classes with the same duck-typed hook that can share it: the Subversion category half (`abilities/bernerd-roster-mechanics.ts`),

## R-B08-8  WHEN `calc.my-attack-matchup`  DONE in this branch

- Kind calc, dispatch key `BoneMoveTypeChartAbAttr`, by-name `fire()` scan in `Pokemon.getAttackTypeEffectiveness`. Same L2 treatment as
  R-B08-7. The sibling by-name scanners (`OffensiveTypeChartOverrideAbAttr`, `WeatherGroundAirborneAbAttr`, `MiracleBladeTypeChartAbAttr`)
  can use it through `alsoDispatchKeys` when their classes are declared.

## R-B08-9  Harness: studio carriers are not plain users of a class  DONE in this branch

- Extermination Vector (20003 attr 4), External Combustion (20018 attr 0) and Malicious Empathy (20006 attr 8, B03) are studio abilities whose
  attr is a CARRIER (canApply, apply, getCondition replaced on the instance by `runtime-components.ts`).
- `harness/sites.ts`: `isRuleCarrier(attr)` (`Object.hasOwn(attr, "canApply")`); `batchSites()` skips carriers; `harness/rebuild.ts` carries
  them over unchanged (listed as carried); `harness/l0.ts` does not ask for a gate binding of a carrier. Other batches that carry the same
  workaround can drop theirs when they merge.

## R-B08-10  Open decisions for the owner (not library work)

a. AbsorbantAbAttr, the x1.5 heal bonus: `HitHealAttr.getHealAmount` (move.ts) finds the class BY NAME and calls `fire(multiplier)`. It never
   goes through `canApply`, so it is not part of the Leech Seed block. It is recorded as the exempt part of the Absorbant declaration. If staff
   should be able to build "my draining moves heal more", the engine needs a WHEN such as `calc.drain-heal` (dispatch key chosen by the
   librarian; the class cannot own two WHENs).
b. ChanceDodgeAbAttr (Ole!, ability 5304) is never dispatched by the engine (`PreDefendAbAttr` is excluded from the callable attr strings and
   nothing scans for the class), so the ability does nothing in battle. Suspected game bug, NOT fixed (a behaviour change). The declaration is
   `exempt`, not claimed as verified: L2 cannot evaluate an attr that nothing calls. Decision needed: dispatch it (then set the status back
   to `decomposed` and run L2) or leave Ole! as it is. `test/.../B08/chance-dodge.test.ts` records the evidence with a spy (zero calls over three
   real turns) and keeps the rebuild draw-for-draw equal to the original.

## R-B08-11  Split the bone rule into engine pieces (BoneMoveTypeChartAbAttr)

- The bone property and the two numbers (immune becomes x1, resisted x2) are now editable params of the class (defaults = old behaviour).
- Still one block, because `Pokemon.getAttackTypeEffectiveness` calls `fire()` by class name. To let staff AND extra conditions or reuse the
  pieces, the engine needs: WHEN `calc.my-attack-matchup` (exists, dispatch key = class name, but nothing is dispatched through it), IF
  `move.has-flag` (move has property X), and DO `effect.set-matchup` (rewrite the type multiplier: immune to a number, resisted times a number).
  Needed by Bone Zone (5091) and Cranisphere (6096). Owner decision whether to route that call site through `applyAbAttrs`.
