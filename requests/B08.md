## R-B08-1  Atom `move.inherent-flag`  (blocks 4 gates of ChanceStatusOnHitAbAttr)

- Label "The move itself has the {flag} property (ignoring what the attacker's abilities do)". Params: the same `flag` select as `move.flag`.
  Requires `move`. Pure.
- Formula: `move.hasFlag(MoveFlags[flag])`. This is NOT `move.flag`, which calls `doesFlagEffectApply({ flag, user: moveUser, target })` and
  so honours Long Reach style abilities and substitute hits. Source: `archetypes/chance-status-on-hit.ts`, `gate` (`inherentlyMakesContact`).
- Why it matters: the non-contact tier ("20% burn on a move that does NOT make contact") must not treat a contact move whose contact was
  suppressed by the attacker's Long Reach as non-contact; the class uses the inherent flag on purpose (comment citing issue #254).
- Needed by: Static (9 attr 1), Flame Body (49 attr 1), White Noise (5358 attr 1), Smoldering Wood (5733 attr 3). Today their `gate` is
  `bindLegacyClosure` (the class keeps running its own gate).

## R-B08-2  Atom `hit.landed-damage`  (blocks the same 4 gates)

- Label "The hit was a damaging one". Requires `hitResult`. Pure.
- Formula: `hitResult` is one of EFFECTIVE, SUPER_EFFECTIVE, NOT_VERY_EFFECTIVE, ONE_HIT_KO (not NO_EFFECT, STATUS, IMMUNE, MISS and so on).
  Source: `archetypes/chance-status-on-hit.ts`, `DAMAGING_HIT_RESULTS`.
- Why: a non-contact STATUS move (Growl) reports `HitResult.STATUS` and must not trigger the non-contact tier (the "Flame Body burns me
  before any attack" report in the class comment).
- With R-B08-1 and R-B08-2 the four gates become, in the ORIGINAL order:
  `all[ not(move.inherent-flag MAKES_CONTACT), hit.landed-damage, status.has other NONE, rng.chance pct ]` (pct 10, 20, 10, 20).
  `bindings.ts` then replaces the four `bindLegacyClosure` lines.

## R-B08-3  Atom `move.drains`  (AbsorbantAbAttr)

- Label "The move heals its user by a share of the damage it deals". Requires `move`. Pure.
- Formula: `move.hasAttr("HitHealAttr")` (the fixed closure `AbsorbantAbAttr` passes to `PostAttackAbAttr`, `archetypes/absorbant.ts`).
- With it, the Leech Seed half of the class could be split as: WHEN after my hit, IF `move.drains` AND the target is not shielded
  from added effects, DO apply SEEDED to the target (the effect `effect.apply-tag` exists). The x1.5 heal bonus is a second job of the same
  class (`HitHealAttr.getHealAmount` finds it BY NAME and calls `fire(multiplier)`), which needs an engine-side query, not a library atom.
  Until then the class is a package.

## R-B08-4  Effect `effect.add-type`  (AddTypeToAttackerOnContactAbAttr)

- Event effect on WHEN `event.after-hit`, label "Give {target} an extra {type} type", params `target` (who) and `type`. `requires: ["other"]`.
- Formula (`archetypes/add-type-to-attacker-on-contact.ts`, `apply`): unless simulated, `target.summonData.addedType = type`,
  `target.updateInfo()`, then queue the `moveTriggers:addType` message with the type name and `getPokemonNameWithAffix(target)`.
  Feasibility that stays with the effect: the target is not Terastallized and does not already have the type.
- Same mechanism as Forest's Curse / Trick-or-Treat. Until it exists the declaration uses `effect.package`.
- Synonyms to carry: extra type, add a type, forest's curse, woodland curse, infect type.

## R-B08-5  Atom `move.targets-one-pokemon` (or an exact `kind` for `move.target-kind`)  (ChanceDodgeAbAttr, optional)

- The class' own set `SINGLE_TARGET_KINDS` is { NEAR_OTHER, OTHER, NEAR_ENEMY, ENEMY_SIDE }. The library's `move.target-kind` "single" is
  { OTHER, NEAR_OTHER, RANDOM_NEAR_ENEMY }: they differ (NEAR_ENEMY and ENEMY_SIDE are in the class set only; RANDOM_NEAR_ENEMY is in the
  library set only). So the class' setting `singleTargetOnly` cannot be an IF yet and stays a boolean param.
- Only worth doing together with the dispatch decision below.

## R-B08-6  Guards `hit-connected-on-another-pokemon` and `blocked-by-effect-shield`  (AteConditionalStatusAbAttr)

- `hit-connected-on-another-pokemon`: label "Does not trigger on a hit that did not connect or on myself". Requires `other`, `hitResult`.
  Formula: `holder !== other && hitResult < HitResult.NO_EFFECT` (`archetypes/ate-conditional.ts`, `guards`).
- `blocked-by-effect-shield`: label "Does not trigger when the target is protected from added effects (Shield Dust)". Requires `other`.
  Formula: `!other.hasAbilityWithAttr("IgnoreMoveEffectsAbAttr")`. It applies only to outcomes that act on the target; the heal outcome is exempt,
  so the guard must be listed per branch, not as a class-wide guard.
- Today both are plain-language lines in the declaration's `feasibility`, and the class keeps them in `guards()`.

## R-B08-7  WHEN `calc.attack-stat`  (blocks AttackStatSubstituteAbAttr, 15 users)

- Kind calc, label "While the game picks the stat my attack uses", group "Stats", dispatch key `AttackStatSubstituteAbAttr`,
  `provides` holder (the attacker), other (the target), move, moveUser, `modifies` "stat".
- The engine does not dispatch it with `applyAbAttrs`: `Pokemon.getBaseDamage` (`field/pokemon.ts`, near 5612) scans
  `source.getAllActiveAbilityAttrs()` for any attr with a `resolveStat` function and calls
  `attr.resolveStat(move, isPhysical, source)`; a non-null answer replaces the attacker's Attack or Sp. Atk. Remove nothing from
  `UNEXPOSED_DISPATCH_KEYS` (the key is not listed there yet); the L0 dispatch-key worklist will need it.
- Needed by: the parked `decl/B08/pending/AttackStatSubstituteAbAttr.decl.pending.ts`, which names `when: "calc.attack-stat"`.
- Other classes that use the same duck-typed `resolveStat` hook and could share this WHEN: the Subversion category half in
  `abilities/bernerd-roster-mechanics.ts` (`resolveStat`), RelativityAbAttr (`resolveOffenseStat`, a sibling hook).
- L2: not reachable by a battle twin, the declaration carries an `l2StaticReason` and the B08 test drives `resolveStat` directly. The L0 test
  "every trigger has an L2 scenario template (or a written reason it is static)" also needs the new id listed in `decomp-l2-reach.json` as unreached
  (verified locally: with the WHEN added and the parked file renamed, per-declaration L0 and L1 identity (17 sites) are clean).

## R-B08-9  Harness: studio carriers must not count as plain users of a class  (blocks a green L1 and L2 for AbsorbantAbAttr)

- Extermination Vector (20003 attr 4) and External Combustion (20018 attr 0) are saved studio abilities whose attr is a CARRIER: a clone of
  Absorbant's attr (`hook` in `er-custom-abilities.json`) whose `canApply`, `apply`, `getCondition` and `getTriggerMessage` are assigned on the
  INSTANCE by `compileAbilityStudioRuntimeComponentRule` (`runtime-components.ts`, near line 606). A plain rebuild of such an attr drops the
  composed rule, so `l1.test.ts` reports "fingerprint differs" and the attr differential reports `canApply` true for the original and false for the
  rebuild, for these two sites only. The same problem was reported by B03 (Malicious Empathy, 20006 attr 8).
- Wanted: `recomposeAttr` throws a plain-language error for an attr with its own `canApply` (`Object.hasOwn(attr, "canApply")`), so the sites
  count as "not rebuilt" (carried over, as a studio rule), or `batchSites()` skips them, and coverage counts them as composition, not as users.
- This chunk verified AbsorbantAbAttr with a LOCAL, UNCOMMITTED filter of exactly that kind in `harness/sites.ts` (L1: 27 declared sites, all
  identical or deliberately not rebuilt; L2: green). The committed tree does not carry the filter, so L1 for AbsorbantAbAttr is red on those two
  sites until the harness owner lands the change.
