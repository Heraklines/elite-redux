# Requests from batch B09 (chunk 2 of 5) to the librarian (B19) and the harness owner (B20)

These are requests, not code. Ids are `R-B09-nn`. Each says what the atom, effect or builder must do and which ability needs it. All
of them come from classes in `archetypes/first-move-priority.ts`, `archetypes/first-turn-stat-multiplier.ts` and
`archetypes/flare-boost-fog-self-burn.ts`.

## Condition atoms

### R-B09-01 `move.inherent-flag { flag }` (group Move)

The move itself has the property printed on it: `move.hasFlag(MoveFlags[flag])`, with NO user and NO flag injection.

- Label: "The move itself has the {flag} property".
- Why the existing `move.flag` is not enough: it calls `doesFlagEffectApply`, which also counts flags that other abilities
  inject (`isMoveFlagInjector`: Rapier turns slicing into horn and horn into slicing; the dance, sound and status injectors of
  Taekkyeon, Festivities and Musical Notes), plus the contact rules. The classes below read `hasFlag`, so mapping them to
  `move.flag` would change behaviour while such an ability is on the field.
- Needed by: Coil Up, Sidewinder, Cutthroat, Edgelord, Curlipede, First Serpent, Head First, Quick Charge (two flags),
  Flicker Jab (two flags) for `FirstFlaggedMovePriorityAbAttr` (9 gates); Cutthroat, Sidewinder, Edgelord, First Serpent, Head
  First, Quick Charge, Flicker Jab for `ConsumeFirstFlaggedMovePriorityAbAttr` (7 gates).
- Needs the `move` slot only. A list of flags is two atoms in an `any`.
- When it exists, the `flags` param of both classes can become editable with a `gateParams` entry.

### R-B09-02 `mon.fainted { who }` (group Party and side)

`pokemon.isFainted()` (hp <= 0, the default `checkStatus = false`), for `holder`, `other` or `ally`.

- Needed by: the four users of `ConsumeFirstFlaggedMovePriorityAbAttr` with `regainOnKo = true` (Sidewinder, Edgelord, First
  Serpent, Head First): their gate is `flag OR target fainted`.
- `hp.at-most` cannot stand in for it (its smallest value is 1 percent, and the percent of max HP is not "zero HP").

### R-B09-03 `mon.first-move-bonus-unspent { who }` (group Time and memory)

True while the one-shot "first-move priority bonus" is still available: `!hasUsedPriority(pokemon)`, i.e. the Symbol
`FirstMovePriority.used` in `pokemon.tempSummonData` is not set (file `archetypes/first-move-priority.ts`, helper
`hasUsedPriority`). The key is module-private today; the library atom must call an exported accessor so both sides read the
same memory (like `time.once-per` with scope `wave` shares `waveData.entryEffectsFired`).

- Needed by: `FirstFlaggedMovePriorityAbAttr` (guards() stage) and `ConsumeFirstFlaggedMoveOnUseAbAttr` (guards() stage), 11
  attrs. Until it exists this memory stays in the class as the "also requires" line.

### R-B09-04 `time.last-move-inherent-flag { flag }` (group Time and memory)

The move the holder used most recently (`pokemon.getLastXMoves(1)[0]`) exists and its printed property is set:
`allMoves[lastMove.move]?.hasFlag(flag) ?? false`. For triggers that provide no `move` slot (here `event.my-move-starts`, the
`ExecutedMoveAbAttr` hook, which passes only the holder; the engine pushes the move to the history just before the call).

- Needed by: Coil Up (5040 attr 1) and Curlipede (5687 attr 2), `ConsumeFirstFlaggedMoveOnUseAbAttr`.

### R-B09-06 `time.no-move-since-entry { who }` (group Time and memory)

The holder has used no move since it came in: `!pokemon.summonData?.moveHistory || pokemon.summonData.moveHistory.length === 0`
(note the `?.` and the empty-list case; both mean true).

- It is NOT `time.first-turn` (`tempSummonData.waveTurnCount === 1`): a holder that sleeps or flinches through turn 1 still
  has an empty history on turn 2, and a holder that has already moved on turn 1 has a non-empty one for the rest of turn 1.
- Needed by: the 8 attrs of `FirstTurnStatMultiplierAbAttr` (Violent Rush x2, Showdown Mode x2, Rapid Response x2,
  Champion's Entrance x2). The `Demolitionist` ability and `doesFlagEffectApply(IGNORE_PROTECT)` already use the same test
  inline (move.ts), so other batches may want it too.

## Effects

### R-B09-05 first-move bonus effects and the first-turn priority clamp (group Moves)

Three effects with a plain "verb first" label each:

1. `effect.spend-first-move-bonus` "Use up my first-move priority bonus": sets the `FirstMovePriority.used` Symbol on
   `tempSummonData` (`setUsedPriority(pokemon, true)`). Used by `ConsumeFirstFlaggedMovePriorityAbAttr` (branch 1) and
   `ConsumeFirstFlaggedMoveOnUseAbAttr`.
2. `effect.restore-first-move-bonus` "Give back my first-move priority bonus": clears it (`setUsedPriority(pokemon, false)`).
   Used by `ConsumeFirstFlaggedMovePriorityAbAttr` (branch 2) and `RearmFirstFlaggedMoveOnMoveAbAttr`.
3. `effect.first-turn-priority-clamp` "Raise priority by 1, but lift negative priority to 0":
   `priority.value = priority.value < 0 ? 0 : priority.value + 1` (a plain `effect.change-priority` would turn -1 into 0 and
   0 into 1 only by coincidence of the amount; it cannot express "negative becomes 0, others +1"). Used by
   `FirstTurnPriorityClampAbAttr` (On the Prowl, Overwatch).

The declarations currently name `effect.arm-effect` (the closest word) for 1 and 2 and `effect.change-priority` for 3.

## Decision for the owner (not a library request)

### R-B09-07 Flare Boost popup in clear weather

`FlareBoostSelfBurnOnSummonAbAttr` has no `canApply`, so the ability popup "Flare Boost" shows on EVERY switch-in, even without
fog, and the fog test sits in `apply`. Moving the fog test into `canApply` would make the weather an editable condition
(`field.weather` or a new `field.fog` atom that calls `isFogWeather`) but would hide the popup when there is no fog: a visible
behaviour change. The declaration is Tier C until the owner decides. If the owner agrees, the follow-up is a pure move of the
three clauses of `selfBurnInFog` into a gate/residual split plus a `field.fog` atom ("Eerie Fog or normal fog is active").
