# Requests from batch B09 (chunks 2 and 3 of 5) to the librarian (B19) and the harness owner (B20)

These are requests, not code. Ids are `R-B09-nn`. Each says what the atom, effect or builder must do and which ability needs it. All
of them come from classes in `archetypes/first-move-priority.ts`, `archetypes/first-turn-stat-multiplier.ts` and
`archetypes/flare-boost-fog-self-burn.ts`.

## Condition atoms

### R-B09-01 `move.inherent-flag { flag }` (group Move)

The move itself has the property printed on it: `move.hasFlag(MoveFlags[flag])`, with NO user and NO flag injection.

- Label: "The move itself has the {flag} property".
- Why the existing `move.flag` is not enough: it calls `doesFlagEffectApply`, which also counts flags that other abilities
  inject (`isMoveFlagInjector`: Rapier turns slicing into horn and horn into slicing; the dance, sound and status injectors of
  Taekkyeon, Festivities and Musical Notes), plus the contact rules. The classes below read `hasFlag`, so mapping them to
  `move.flag` would change behaviour while such an ability is on the field.
- Needed by: Coil Up, Sidewinder, Cutthroat, Edgelord, Curlipede, First Serpent, Head First, Quick Charge (two flags),
  Flicker Jab (two flags) for `FirstFlaggedMovePriorityAbAttr` (9 gates); Cutthroat, Sidewinder, Edgelord, First Serpent, Head
  First, Quick Charge, Flicker Jab for `ConsumeFirstFlaggedMovePriorityAbAttr` (7 gates).
- Needs the `move` slot only. A list of flags is two atoms in an `any`.
- When it exists, the `flags` param of both classes can become editable with a `gateParams` entry.

### R-B09-02 `mon.fainted { who }` (group Party and side)

`pokemon.isFainted()` (hp <= 0, the default `checkStatus = false`), for `holder`, `other` or `ally`.

- Needed by: the four users of `ConsumeFirstFlaggedMovePriorityAbAttr` with `regainOnKo = true` (Sidewinder, Edgelord, First
  Serpent, Head First): their gate is `flag OR target fainted`.
- `hp.at-most` cannot stand in for it (its smallest value is 1 percent, and the percent of max HP is not "zero HP").

### R-B09-03 `mon.first-move-bonus-unspent { who }` (group Time and memory)

True while the one-shot "first-move priority bonus" is still available: `!hasUsedPriority(pokemon)`, i.e. the Symbol
`FirstMovePriority.used` in `pokemon.tempSummonData` is not set (file `archetypes/first-move-priority.ts`, helper
`hasUsedPriority`). The key is module-private today; the library atom must call an exported accessor so both sides read the
same memory (like `time.once-per` with scope `wave` shares `waveData.entryEffectsFired`).

- Needed by: `FirstFlaggedMovePriorityAbAttr` (guards() stage) and `ConsumeFirstFlaggedMoveOnUseAbAttr` (guards() stage), 11
  attrs. Until it exists this memory stays in the class as the "also requires" line.

### R-B09-04 `time.last-move-inherent-flag { flag }` (group Time and memory)

The move the holder used most recently (`pokemon.getLastXMoves(1)[0]`) exists and its printed property is set:
`allMoves[lastMove.move]?.hasFlag(flag) ?? false`. For triggers that provide no `move` slot (here `event.my-move-starts`, the
`ExecutedMoveAbAttr` hook, which passes only the holder; the engine pushes the move to the history just before the call).

- Needed by: Coil Up (5040 attr 1) and Curlipede (5687 attr 2), `ConsumeFirstFlaggedMoveOnUseAbAttr`.

### R-B09-06 `time.no-move-since-entry { who }` (group Time and memory)

The holder has used no move since it came in: `!pokemon.summonData?.moveHistory || pokemon.summonData.moveHistory.length === 0`
(note the `?.` and the empty-list case; both mean true).

- It is NOT `time.first-turn` (`tempSummonData.waveTurnCount === 1`): a holder that sleeps or flinches through turn 1 still
  has an empty history on turn 2, and a holder that has already moved on turn 1 has a non-empty one for the rest of turn 1.
- Needed by: the 8 attrs of `FirstTurnStatMultiplierAbAttr` (Violent Rush x2, Showdown Mode x2, Rapid Response x2,
  Champion's Entrance x2). The `Demolitionist` ability and `doesFlagEffectApply(IGNORE_PROTECT)` already use the same test
  inline (move.ts), so other batches may want it too.

## Effects

### R-B09-05 first-move bonus effects and the first-turn priority clamp (group Moves)

Three effects with a plain "verb first" label each:

1. `effect.spend-first-move-bonus` "Use up my first-move priority bonus": sets the `FirstMovePriority.used` Symbol on
   `tempSummonData` (`setUsedPriority(pokemon, true)`). Used by `ConsumeFirstFlaggedMovePriorityAbAttr` (branch 1) and
   `ConsumeFirstFlaggedMoveOnUseAbAttr`.
2. `effect.restore-first-move-bonus` "Give back my first-move priority bonus": clears it (`setUsedPriority(pokemon, false)`).
   Used by `ConsumeFirstFlaggedMovePriorityAbAttr` (branch 2) and `RearmFirstFlaggedMoveOnMoveAbAttr`.
3. `effect.first-turn-priority-clamp` "Raise priority by 1, but lift negative priority to 0":
   `priority.value = priority.value < 0 ? 0 : priority.value + 1` (a plain `effect.change-priority` would turn -1 into 0 and
   0 into 1 only by coincidence of the amount; it cannot express "negative becomes 0, others +1"). Used by
   `FirstTurnPriorityClampAbAttr` (On the Prowl, Overwatch).

The declarations currently name `effect.arm-effect` (the closest word) for 1 and 2 and `effect.change-priority` for 3.

## Decision for the owner (not a library request)

### R-B09-07 Flare Boost popup in clear weather

`FlareBoostSelfBurnOnSummonAbAttr` has no `canApply`, so the ability popup "Flare Boost" shows on EVERY switch-in, even without
fog, and the fog test sits in `apply`. Moving the fog test into `canApply` would make the weather an editable condition
(`field.weather` or a new `field.fog` atom that calls `isFogWeather`) but would hide the popup when there is no fog: a visible
behaviour change. The declaration is Tier C until the owner decides. If the owner agrees, the follow-up is a pure move of the
three clauses of `selfBurnInFog` into a gate/residual split plus a `field.fog` atom ("Eerie Fog or normal fog is active").

### R-B09-12 `move.flag-mask { flags }` (group Move)

The move has ANY of several printed or injected properties tested as ONE combined flag, exactly
`move.doesFlagEffectApply({ flag: A | B, user })` where `A | B` is a bit mask. Needed by Dual Wield (5169), Minigun (5996 attr 2) and
Two-Chambered (6086), whose filter is `PULSE_MOVE | SLICING_MOVE` (Mega Launcher or Keen Edge moves), for both
`HitMultiplierAbAttr` and `HitMultiplierPowerAbAttr` (6 gates, all legacy-closure now).

- Why `{ any: [move.flag PULSE, move.flag SLICING] }` is not equal: `doesFlagEffectApply` first tests `hasFlag(mask)` (any bit set) and, when
  that fails, asks every flag injector `attr.injects(mask, move)`, which compares the flag by EQUALITY (`flag !== this.injectFlag`
  in `MoveFlagInjectionAbAttr`, `flag === SLICING_MOVE` in Rapier). A mask therefore never matches an injection, while the single
  flag does (a horn move counts as slicing under Rapier). The atom must call the same function with the mask.
- Needs the `move` and `moveUser` slots.

### R-B09-13 let the engine read the studio gate instead of the class filter (move.ts:8115-8124)

`Move.apply` of the flinch attr reads `a.getFilter()` of every `HitMultiplierAbAttr` on the user to decide whether the first
strike keeps its flinch chance. A staff rule that replaces the gate of `HitMultiplierAbAttr` changes the hits but not that flinch
rule. Route it through the same gate (for example a method `matches(user, move)` on the class that calls `gate`) when the foundation
converts the call site; class agents do not edit `move.ts`.

### R-B09-14 effect `effect.scale-stat-with-missing-hp { stat, atFullHp, atZeroHp }` (group Stats)

"Multiply a stat by an amount that grows (or shrinks) in a straight line as my HP drops": `min + (max - min) * (1 - clamp(hp / maxHp, 0, 1))`
(`HpScalingStatMultiplierAbAttr.multiplierAt`). Needed by Last Stand (5338 attr 0 and 1). Until it exists the declaration is a
package (`effect.package`). `abilities/pressure-vessel.ts` repeats the same formula in its own class (outside this batch).

trigger, after stamping the per-turn memory on the holder and on every receiver (R-B09-25). `effect.stat-stage` names one fixed stat and
amount, so it cannot repeat "whatever just changed". Needs the `stat` and `stages` slots. Needed by Sharing Is Caring (5290).

## Safety rules and conditions

### R-B09-25 guard or atom "I have not already shared a stat change this turn" (group Time and memory)

`FieldStatShareAbAttr.guards`: `(pokemon[Symbol("FieldStatShare.lastTurn")] ?? -1) !== currentBattle.turn`. A reentrancy rule: without it the copied
changes would be copied again for ever, so it is a safety rule (guard) and not a condition. The Symbol is module-private; the library form has to
call an exported accessor so that both sides read the same memory (like R-B09-03). Needed by Sharing Is Caring. Until it exists the rule stays in the class
as the "also requires" line.

### R-B09-26 guard "Only after the last strike of my multi-hit move" (group Move)

`FireUseFormChangeAbAttr.guards`: `!(holder.turnData.hitsLeft > 1)`, for a trigger where the holder is the attacker (`event.after-my-hit`). The existing
guard `after-final-hit` reads `frame.other.turnData.hitsLeft` and returns true when `other` has no last move: it is made for the damage-taken hook where
`other` is the attacker, so for `event.after-my-hit` (where `other` is the target) it would read the wrong Pokemon. Either a second guard that reads the
holder, or let `after-final-hit` pick the attacker from the WHEN (`WHEN_MOVE_USER`). Needed by Flammable Coat (5373 attr 0).

## Harness limitation found by this chunk

### R-B09-28 L2 twin of an ability whose OTHER attrs read the ability by identity (B20)

The L2 twin of Electrodynamics (6062) is red although no attr of this chunk is involved: the first difference is attr 0,
`ElectrodynamicsTerrainPowerAbAttr` (`abilities/fakemon-pitch-raichu.ts:267-275`), whose closure calls `isRaichuTerrainActiveForMove`, and that
asks `pokemon.hasAbility(RAICHU_ELECTRODYNAMICS_ABILITY)` (line 189). The shadow ability (id 29002) is not Electrodynamics, so the original
boosts Electric moves in the "holder attacks" scenario (`-a1!`) and the twin does not (`-a0.`); the foe HP differs by 2 to 4 afterwards. The
harness needs either an alias so that `hasAbility(id)` also answers true for the twin of that id, or a rule that skips attrs which are read
by identity. The class of this chunk in that ability (`GroundedEntryHazardImmunityAbAttr`, attr 3) is a presence marker proven by
the L1 identity and differential checks. All other abilities of this chunk (Shield Dust, Air Lock, Sharing Is Caring, Battle Aura, Flammable Coat,
Spore Bed) pass the L2 twin.

   (`immunity-with-absorb.ts`, `TypeAbsorbHealAbAttr.apply`). Used by Poison Absorb (5082 attr 1) and Ice Plumes (5571 attr 2).
2. `effect.immune-and-change-stat { type, stat, stages }` "Be immune to a type and change a stat when hit by it": `typeMultiplier = 0`,
   `cancelled = true`, and when not simulated a `StatStageChangePhase` on the holder (`TypeImmunityStatStageChangeAbAttr.apply`,
   `ab-attrs.ts`). Used by Aerodynamics (5020 attr 0) and Fluttering Spirit (6019 attr 4).
3. `effect.immune-and-raise-best-attack { type, stages }`: same, but the stat is `getStat(SPATK, false) > getStat(ATK, false) ? SPATK : ATK`
   (a tie picks Attack; `false` means "without stat stages", see the class notes). Used by Ice Dew (5116 attr 1), Heat Sink (5566 attr 1)
   and Alluring Skull (5965 attr 1).

All three need the `calc.move-immunity` frame (`pokemon`, `typeMultiplier`, `cancelled`, `simulated`).

### R-B09-31 effect `effect.multiply-incoming-accuracy { multiplier }` (group Moves)

"Multiply the accuracy of moves aimed at me by {multiplier}": `accuracy.value *= multiplier` on the `calc.incoming-accuracy` frame
(`Move.calculateBattleAccuracy`, move.ts:1239). The class leaves the never-miss marker (`accuracy < 0`) alone and has an optional rule
"ignore spread moves" (`singleTargetOnly`); both could be a guard and an atom (`move.target-kind` already exists for the second).
Used by Bad Luck (5072 attr 2) and Scarecrow (5522 attr 3). Today the block itself is the effect and the declaration names none.

## Guards and atoms

### R-B09-32 guard `credited-with-the-knock-out` (group Time and memory)

True when the Pokemon that fainted took its latest direct attack from the holder: `victim.turnData.attacksReceived?.[0]?.sourceId ===
holder.id` (`koLandedByDirectHit`, `archetypes/lifesteal.ts`). The faint phase hands `PostKnockOutAbAttr` to EVERY Pokemon on the field,
so this is what turns "something fainted" into "I knocked it out"; weather, poison and hazard knock-outs credit nobody. Removing it would be
a bug (bystanders heal and loot), so it is a guard, not a condition. Needed by `LifestealOnKoAbAttr` (18 attrs) and `ScavengerLootAbAttr`
(2). Until it exists it is written as an "also requires" line.

### R-B09-33 add `MoveCategoryOverrideAbAttr` to the `flagKeys` of WHEN `while.active`

`vocabulary/when-registry.ts`. Same one-line data change as R-B09-11 and R-B09-24: the class is dispatched by name from
`Pokemon.getAttackDamage` (pokemon.ts:5854), never by `applyAbAttrs`, so its declaration uses `when: "while.active"` and L0 needs the
class name in that list. The line is already in this worktree (B09 chunk 4 added it, like chunks 1 and 3 did for their markers).

### R-B09-34 effect "Change the damage category of my moves with a property" and an engine route (group Moves)

`effect.change-move-category { flag, category }`. The engine finds the attr by the duck-typed method `resolveCategory(move, user)` and
the property test (`doesFlagEffectApply({ flag, user })`, or `hasFlag` when no user is passed) is part of the engine query, so staff can
change the two settings but cannot swap the property test for another condition. When the foundation converts `pokemon.ts:5854`, route it
through a gate on the class (like R-B09-13) so the test becomes an editable `move.flag` atom. Used by Mystic Blades (5235), Blade's Essence
(5242), Best Offense (5545), Magus Blades (5547), Sinister Claws (5712) and Spiritual Saber (6065).

### R-B09-35 `rng.chance` at 100 percent draws no number, `ScavengerLootAbAttr` always draws

The library atom answers true without a draw at `pct >= 100`; the class still draws `randBattleSeedInt(100)` and compares it with
`round(chance * 100)`. Both users are at 50, so nothing differs today, but a staff rule that sets the loot chance to 100 shifts the random
sequence by one draw per knock-out. Either keep the draw in the atom at 100 or accept it. (No class change was made.)
