# Requests from batch B12 (chunk 1 of 5) to the librarian (B19) and the harness owner (B20)

## For the librarian (B19)

### R-B12-01  Atom `ko.credited-to-me`  (StatTriggerOnKoAbAttr, nine users are legacy-closure until it exists)

- Label: "I am the Pokemon credited with the knock out". Group "Party" (or "Time and memory"). `requires: ["other"]` (the fainted Pokemon,
  slot `other` of "When I knock out a Pokemon"). No params. `pure: true`.
- Formula: `other.turnData?.attacksReceived?.[0]?.sourceId === holder.id`.
  Source: `src/data/elite-redux/archetypes/stat-trigger-on-event.ts`, `StatTriggerOnKoAbAttr.gate` clause 3 (the Moxie semantics: the victim's
  most recent attacker is the holder). The library trigger carries the same test as part of its moment gate
  (`compile-composition.ts` MOMENT_GATES `event.on-ko`), so the atom just exposes it.
- Same predicate as B09's R-B09-32 (guard `credited-with-the-knock-out`); the librarian may keep one of the two names. As an atom it is
  better: Forsaken Heart (any faint) is the same rule WITHOUT it, which is a design choice staff may flip.
- Binding of the nine users once it exists: `all[ not side.is{self}, ko.credited-to-me ]`. Users (all legacy-closure today, slot `gate`):
  ChillngNeigh (5003 attr 0), Adrenaline Rush (5185 attr 0), Super Strain (5217 attr 0), Hubris (5262 attr 0), Haunting Frenzy (5301 attr 1),
  Dragon's Ritual (5400 attr 0), Breezy Neigh (5559 attr 0), Hydra (5630 attr 1), As One (20022 attr 0).
- Also correct the label of WHEN `event.on-ko` ("When I knock out a Pokemon"): `PostKnockOutAbAttr` is dispatched for EVERY Pokemon on the field
  once ANY Pokemon faints (`faint-phase.ts:268`), it is not "I knock out". B03 asked for the same fix.

### R-B12-02  Effect `effect.count-event`  (FaintCountTriggerAbAttr, the counter half of Soul Harvest)

- Label: "Add one to a counter that lasts this battle". Params: `counter` (text, the name of the counter, default "faints"), `amount`
  (number, default 1).
- Formula: `pokemon.battleData[counterField] = (pokemon.battleData[counterField] ?? 0) + amount`, skipped when `simulated`.
  Source: `archetypes/stat-multiplier-per-faint.ts`, `FaintCountTriggerAbAttr.apply` (field `erSoulHarvestFaintCount`).
- Needs a matching read atom `count.compare{counter, cmp, n}` ("My counter is at least N") so other rules can read the count.
- Today the class is a package (effect only); its trigger and its condition (`not side.is{self}`) are already separate blocks.

### R-B12-03  Effect `effect.multiply-stat-per-count`  (PerFaintStatMultiplierAbAttr, the stat half of Soul Harvest)

- Label: "Grow a stat by a percent for every count". Params: `stat` (select), `percent` (number 0.5 to 100, step 0.5), `counter` (the same
  counter name as R-B12-02).
- Calc effect on `calc.stat-value`: `statVal.value *= 1 + percent / 100 * count`, where count is the counter of R-B12-02 (0 when unset).
  Source: `archetypes/stat-multiplier-per-faint.ts`, `PerFaintStatMultiplierAbAttr.apply` (`1 + perFaint * faintCount(pokemon)`). The
  existing `effect.multiply-stat` is a fixed multiplier and cannot express it. Users: Soul Harvest (5589 attrs 1, 2, 3: Attack, Sp. Atk and
  Sp. Def, 5 percent).

### R-B12-04  Atom `move.has-built-in-flag{flag}`  (StatTriggerOnHitAbAttr user Super Hot Goo; same atom as R-B01-10)

- Formula `move.hasFlag(MoveFlags[flag])`, source `move.ts:475`. It reads the move's own flag bit and does NOT ask the attacker's abilities.
  `move.flag` calls `doesFlagEffectApply` and is false for an attacker with Long Reach, for Punching Glove and for a substitute.
- User: Super Hot Goo (5199 attr 1), gate `move.hasFlag(MAKES_CONTACT)`. Its binding becomes `move.has-built-in-flag{MAKES_CONTACT}`.
  B12's own test proves the class reads the plain flag (it compares the class with `move.hasFlag` over every move).

### R-B12-05  Atom or safety rule "the stat change was caused by someone else", plus the `selfTarget` frame field  (the two stat-lowered classes)

- Label (atom): "The change was not caused by my own move". Formula `!params.selfTarget`. Source: `StatTriggerOnStatLoweredAbAttr.residual` and
  `StatTriggerOnAllyStatLoweredAbAttr.residual` in `stat-trigger-on-event.ts`; `stat-stage-change-phase.ts:357` passes `selfTarget`.
- It needs a new slot (or a frame field) because `frameFromAttrParams` does not copy `selfTarget`; WHENs `event.stat-changed` and
  `event.ally-stat-changed` would provide it. It is the same rule as B02-8 (Defiant, Competitive).
- Today it stays in the class as the Tier B `residual` (checked after the gate `stage.just-changed{lowered}`), so all 19 users are bound; moving it
  into the gate would let staff drop it ("react even to my own drops"). If the librarian prefers a locked rule, register a guard
  `not-self-caused-stat-change` instead.

### R-B12-06  `effect.stat-stage`: several stats at once and "once for each stat lowered"  (all stat-trigger classes)

- The class lists several stat changes (Attack +1 AND Speed +1) and, in scope "each stat lowered", repeats each one `stats.length` times by
  multiplying the stages (`StatTriggerOnStatLoweredAbAttr.apply`, `StatTriggerOnAllyStatLoweredAbAttr.apply`, `applyStatChanges` in
  `stat-trigger-on-event.ts`). `effect.stat-stage` has one stat and one number of stages.
- Needed: either a list form (`changes: "Attack +1, Speed +2"`) or the composition allowing several `effect.stat-stage` blocks (it does), plus a
  `times` option: "Repeat once for each stat that was lowered" (the number of stats in the event). Stages above 6 are accepted by the class and
  clamped by the phase (Petal Shield asks for +12).

### R-B12-07  Guards for engine moments  (StatTriggerOnHitAbAttr, StatusCascadeAbAttr)

- `hit-landed`: "Only after a hit that landed and did damage": `hitResult < HitResult.NO_EFFECT`. It is the first clause of
  `StatTriggerOnHitAbAttr.guards`, and it is already part of the moment gate of "After I am hit" (MOMENT_GATES `event.after-hit`, which also
  asks `damage > 0`; the class does not). Today it stays a class guard (not removable); register it so the declaration can list it.
- `target-still-standing`: "Only while the target has not fainted": `opponent !== undefined && !opponent.isFainted()`. First clause of
  `StatusCascadeAbAttr.guards` (trigger "After my attack lands").

### R-B12-08  A real list control for staff  (UI, all stat-trigger classes and the hit filter)

- The classes take a LIST of stat changes (`[{stat, stages}, ...]`) and a filter object (`{types, flags}`). `ParamControl` has no list or
  multi-select control, so B12 declares them as one plain-words text setting each ("Attack +1, Speed +2", "Fire, Flying, Contact") with a codec
  (`decl/B12/b12-chunk1-codecs.ts`). An editor control "list of (stat, number of stages)" and a "types and properties" multi-select would
  be friendlier than typing. Not blocking.

  then the declaration carries an `l2StaticReason`, and B12's own test covers the class.
- Not twinned by the shared L2 until the atoms above exist: the nine credited Ko users and Super Hot Goo (their only gate is a legacy-closure, so
  L2 leaves them out as in R-B01-27).

### R-B12-15  Effect "open a named timed window" and a once-per whose write waits for the effect  (ActivateOncePerBattleEntryWindowAbAttr)

- Effect: `pokemon.waveData.entryEffectsFired.add(key); pokemon.tempSummonData.abilityEntryWindows.add(key)` (the window resets when I switch out; the
  per-wave set resets every wave), skipped when simulated. Params: `key` (text). Source: `archetypes/time-limited-effectiveness-floor.ts`, `apply`.
- Why the existing atom does not work: `time.once-per{wave,key}` reads and writes the same set, but `buildAttr`'s carrier commits the write BEFORE the
  class's `apply`, and `apply` returns early when the key is present, so the window is never opened (B12/chunk2.test.ts shows it). With a library effect
  that owns both writes (or a commit that runs after the effect) the gate can bind as `time.once-per{wave, key}`; the declaration's `gateParams` already
  maps `key`. User: Forewarn (108 attr 1, key `upgrade:forewarn:two-turn-soothsayer`).
- Naming note: the class says "once per battle" but the memory (`waveData`) is per WAVE.
