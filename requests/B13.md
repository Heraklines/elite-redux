# Requests from batch B13 (chunk 1 of 6) to the librarian (B19) and the harness owner (B20)

Not code. One entry per request: id, what it must do, the source line, and which class needs it. Chunk 1 owns these
classes (all in `src/data/elite-redux/abilities/newcomer-signature-mechanics.ts`): FinalSeasonEntryAbAttr,
FinalSeasonFogAbAttr, FinalSeasonPowerAbAttr, FoulHarvestAbAttr, PorousResetAbAttr, PorousSoundReductionAbAttr,
PorousChargeAbAttr, PorousPowerAbAttr. Users: Final Season (5972), Foul Harvest (5973), Porous (5974), one each.

Every request below is the reason a clause is a `legacy-closure` binding (or sits in the class's `guards` / `residual`)
today. When the atom exists, the owning agent replaces the binding by the real spec and moves the clause into the gate.

## Conditions (IF atoms)

### R-B13-1  `entry.voluntary-switch-in`  (FinalSeasonEntryAbAttr, gate)

- Label: "I came in by a deliberate switch (not as the first Pokemon and not as a replacement for a fainted one)".
  Group "Time and memory" or "Party and side". Requires `holder`. Pure.
- Formula: `VOLUNTARY_ENTRY.has(pokemon)` (`newcomer-signature-mechanics.ts:134`, set `:120` by
  `markGenuineVoluntaryEntry`, called from `phases/switch-summon-phase.ts:462` when `switchType === SWITCH` and the turn
  command of the field slot is `Command.POKEMON`). The flag is spent (deleted) by `FinalSeasonEntryAbAttr.apply`, so the
  atom must NOT delete it; spending stays in the effect (as the `time.once-per` write waits for apply).
- Synonyms: "voluntary switch", "chosen switch", "manual switch-in", "not a faint replacement", "switched in by choice".

### R-B13-2  `time.armed`  (FinalSeasonFogAbAttr, gate)

- Label: "An earlier effect of mine readied this (armed)". Params: `key` (text). Requires `holder`. Pure. The effect side
  already exists as `effect.arm-effect` (`armKey`); this is its missing condition side.
- Formula: `FINAL_SEASON_PENDING_FOG.has(pokemon)` (`newcomer-signature-mechanics.ts:161`; added at `:146` by the entry
  attr's apply, deleted at `:165` by the fog attr's apply). The memory must be per Pokemon (WeakSet), keyed by `key`.
- Synonyms: "armed", "readied earlier", "delayed effect is ready", "queued effect".

### R-B13-3  `hit.dealt-damage`  (FoulHarvestAbAttr gate clause 2, PorousChargeAbAttr gate clause 1)

- Label: "The hit really dealt damage (more than 0)". Requires `damage`. Pure.
- Formula: `params.damage > 0` (`newcomer-signature-mechanics.ts:263` and `:377`). The `damage` slot of the post-hit
  WHENs (`event.after-hit`, `event.after-my-hit`) is the raw engine value.
- Synonyms: "took damage", "damage was dealt", "not a status move that did nothing".

### R-B13-4  `hit.not-blocked`  (FoulHarvestAbAttr gate clause 3, PorousChargeAbAttr gate clause 2)

- Label: "The hit was not blocked or immune". Requires `hitResult`. Pure.
- Formula: `params.hitResult < HitResult.NO_EFFECT` (`newcomer-signature-mechanics.ts:263` and `:377`); `HitResult`
  orders EFFECTIVE, SUPER_EFFECTIVE, NOT_VERY_EFFECTIVE ... below NO_EFFECT, FAIL, MISS, PROTECTED ... above.
- Synonyms: "hit landed", "not immune", "not missed", "connected", "not protected".

### R-B13-5  `time.new-move-of-mine`  (FoulHarvestAbAttr gate clause 4)

- Label: "This is a move of mine that this effect has not counted yet (a multi-hit move counts once)". Requires `holder`.
  Impure only in the sense that it needs per-Pokemon memory; the READ is pure, the WRITE waits for apply (like
  `time.once-per`).
- Formula: `const record = pokemon.getLastXMoves(1)[0]; return !!record && FOUL_HARVEST[pokemon].lastMoveRecord !== record`
  (`newcomer-signature-mechanics.ts:264-266`; written by apply at `:272`, which stores the record BEFORE its simulated
  check, see oddities in the declaration). The memory is the identity of the move-history record object.
- Synonyms: "once per move", "count a multi-hit move once", "new move".

### R-B13-6  `time.new-move-of-foe`  (PorousChargeAbAttr gate clause 3)

- Same as R-B13-5 but for the FOE's last move record: `porousState(pokemon).lastMoveRecord !== opponent.getLastXMoves(1)[0]`
  (`newcomer-signature-mechanics.ts:377`; the record is written by apply at `:381`, keyed by the foe's record, held in
  the holder's Porous state). Parametrise R-B13-5 and R-B13-6 as ONE atom `time.new-move{who: holder/other, key}` if
  that is simpler. Note the Porous version has no `!!record` test: with no foe record at all, `undefined !== undefined` is false, so right after a reset nothing counts until the foe has a move on record.
- Synonyms: "once per foe move", "multi-hit counts once".

### R-B13-7  `field.weather-set-by-me`  (FinalSeasonPowerAbAttr guards, clauses 1 and 2)

- Label: "The weather on the field is the one I set myself". Params: `weather` (select, optional). Requires `holder`. Pure.
- Formula (exact, as it is today): `finalSeasonFogOwner === pokemon && finalSeasonFogInstance === globalScene.arena.weather`
  (`newcomer-signature-mechanics.ts:174`, owner and instance written at `:167` by `FinalSeasonFogAbAttr.apply` after
  `trySetWeather` succeeded). A generic version could read `arena.weather.sourceEntityId === pokemon.id` (the Weather
  object carries `sourceEntityId`, `data/weather.ts:54`), but that is NOT identical: it would also count a fog the same
  Pokemon set by another means, and it ignores the "still the same Weather instance" check. Keep the exact check unless
  the owner accepts the difference. Today these two clauses are the class's `guards`, listed to staff as an "also
  requires" line.
- Synonyms: "my own weather", "weather I summoned", "weather set by me", "my fog".

### R-B13-8  `mon.has-stored-charge`  (PorousPowerAbAttr residual)

- Label: "I have at least {n} stored impact charge(s)". Params: `n` (number, default 1), `key` (text). Requires `holder`.
- Formula: `porousState(pokemon).stacks > 0` (`newcomer-signature-mechanics.ts:393`, counter incremented at `:382` by
  PorousChargeAbAttr, capped at 3, cleared by PorousResetAbAttr and by PorousPowerAbAttr.apply when not simulated).
  Needs the shared "charge counter" memory of R-B13-9. Today it is the class's `residual` (second clause, after the move
  type), listed to staff as an "also requires" line.

## Effects (DO blocks) and memory

### R-B13-9  charge counter memory: `effect.store-charge`, `effect.spend-charges`, `effect.reset-charges`, `time.charges`

- `effect.store-charge{key, max}`: "Store 1 charge, up to {max}" (PorousChargeAbAttr.apply: `stacks = min(3, stacks + 1)`,
  record the counted foe move, show a message).
- `effect.reset-charges{key}`: "Forget my stored charges" (PorousResetAbAttr.apply, one assignment).
- `calc effect multiply-power-per-charge{key, perCharge}`: "Multiply the move's power by 1 + {perCharge} per stored
  charge, then spend them" (PorousPowerAbAttr.apply: `power *= 1 + 0.25 * stacks`; when not simulated `stacks = 0` and a
  message). The spend must stay inside this effect because the multiplier is read from the counter first.
- Condition side: `time.charges{key, cmp, n}` (R-B13-8). The memory must be per Pokemon (WeakMap), shared by key.
- `effect.arm-effect` (exists) has no count and no cap, so it cannot replace these.

### R-B13-10  `effect.drain-pp`  (FoulHarvestAbAttr.apply)

- Label: "Drain {amount} PP from a foe's move". Params: `amount` (1), `which` ("the move it used last, or a random one").
- Formula (`newcomer-signature-mechanics.ts:275-288`): the foe's usable moves (`moveId !== NONE`); the move it executed
  last (`LAST_EXECUTED_MOVE`, by name, filled by `recordSignatureExecutedMove` from `move-effect-phase.ts:453`) when it is
  still in its moveset, ELSE `moveset[pokemon.randBattleSeedInt(moveset.length)]` (the draw happens here, before the
  "no PP left" test); `selected.ppUsed++` when the move has PP left. The effect must keep that draw position.

### R-B13-11  a WHEN and effect for the drain-heal bonus  (FoulHarvestAbAttr, outside the attr)

- The second half of Foul Harvest is not in the attr: `HitHealAttr.apply` (`data/moves/move.ts:3295`) calls
  `applyFoulHarvestDrainBonus` (`newcomer-signature-mechanics.ts:294`), which finds the ability by class name
  (`hasAttr(user, "FoulHarvestAbAttr")`) and adds `floor(singleHitDamageDealt * 0.25 * charges)`, spends one charge and
  gives 1 PP back. A WHEN "While the game calculates how much a draining move heals me" (calc, `modifies: "heal"`)
  would let staff express it. Until then the decomposition of the class does not describe it; it is recorded here and
  in the declaration's notes.

## For the librarian (B19): a WHEN dispatch key fix

### R-B13-12  `calc.move-power` dispatch key

- `calc.move-power` is registered with `dispatchKey: "MovePowerBoostAbAttr"`, but the engine dispatches
  `applyAbAttrs("VariableMovePowerAbAttr", ...)` (`data/moves/move.ts:1338` and `:1509`), so the reach probe reports the
  WHEN as unreached (`decomp-l2-reach.json`: "the engine never evaluated a MovePowerBoostAbAttr attr of the holder").
  Making `VariableMovePowerAbAttr` the primary key (and keeping `MovePowerBoostAbAttr` in `alsoDispatchKeys`) would make
  the shared template reach it. FinalSeasonPowerAbAttr and PorousPowerAbAttr carry an `l2StaticReason` until then.

## For the harness owner (B20)

### R-B13-13  parameterise the hard-coded numbers? (a decision for the owner, no harness change)

- None of the eight classes takes a number through its constructor (2 turns of Quash, 5 turns of fog, 1.3x, 3 charges,
  25% per charge, 0.5x for sound moves, 1 PP are literals in `apply` or in the `super(...)` call). The declarations
  therefore have no params and each says so with `noParamsReason`. To let staff tune them, the class owner would add
  trailing constructor arguments with the current values as defaults (no behaviour change). That edit is outside the
  "canApply split only" rule of the batch, so it was not made; it is listed here for a decision.
