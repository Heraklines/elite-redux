# Library requests from batch B17 (for the librarian, B19)

Plain list, not code. Each entry says what is needed, the exact formula and source, and which class needs it.
Chunk 1 of B17 (LingeringMuskEndureAbAttr, LingeringMuskPostTurnAbAttr, ErMagicianStealAbAttr, MetallosisPoisonAbAttr,
MoxibustionAbAttr, MutualDestructionPostFaintAbAttr, OracleEntryAbAttr, OracleGuardTickAbAttr). Later chunks append below.

Ids marked "proposed" are suggestions; the librarian may rename them but must keep the formula.

## Conditions (atoms)

### R1. `hit.would-knock-out` (proposed): "The hit would knock me out"
- Formula: `damage >= holder.hp` (the frame's effective damage against my current HP).
- Source: `src/data/elite-redux/archetypes/pre-faint-revive.ts:171` (`if (damage.value < pokemon.hp) return false`) and `ab-attrs.ts:339` (`damage.value >= pokemon.hp`).
- Slots: `holder`, `damage` (WHEN `calc.damage-taken` provides them).
- Needed by: LingeringMuskEndureAbAttr (Lingering Musk). Also the inherited rule of PreFaintReviveAbAttr (B11) and Sturdy.
- Note for B11 / the librarian: the clauses of `PreFaintReviveAbAttr.canApply` (HP gate, max HP above 1, the knockout test, the once-per-turn marker) would have to be split into guards / gate / residual in that class so that its subclasses can expose them; I may not edit that file.

### R3. `time.marker-set` (proposed): "A marker is set on me" (memory flag)
- Formula: reads the ER provenance memory of a scope: `scopeData.erAbilityProvenance.includes(key)` for `match: "exact"`, `scopeData.erAbilityProvenance.some(v => v.startsWith(key))` for `match: "prefix"`.
- Params: `scope` (`battle` = `pokemon.battleData`, `switch-in` = `pokemon.summonData`, `turn` = `pokemon.turnData`), `key` (text), `match` (exact or prefix). Pure; never writes.
- Sources: `fakemon-pitch-mechanics.ts:630` OracleEntryAbAttr gate (`!battleData.erAbilityProvenance.includes("oracle:first-entry")`, used negated), `:664` OracleGuardTickAbAttr gate (`summonData.erAbilityProvenance.some(v => v.startsWith("oracle:guard:"))`).
- The same atom is needed for the marker of Lingering Musk, which today is a loose field: `bernerd-roster-mechanics.ts:233` reads `tempSummonData.lingeringMuskFaint`. Either the atom also accepts a named flag on `tempSummonData`, or B14 moves it into the provenance memory later (a separate behaviour-neutral change for the owner to decide).
- Needed by: LingeringMuskPostTurnAbAttr, OracleEntryAbAttr, OracleGuardTickAbAttr. Many other ER classes keep markers in this same memory (Eulogy, Splash Damage, Somniloquy, Booby Trap, Celestial Jelly), so the atom pays off beyond this batch.
- Today these three gates are written as legacy-closure, so those three attrs cannot be rebuilt from the library (status legacy-closure-pending-request).

### R5. `hit.was-critical` (proposed): "The hit was a critical hit"
- Formula: `!!other.turnData.attacksReceived[0]?.critical` (index 0 is the NEWEST record; `move-effect-phase.ts:989` unshifts).
- Source: `fakemon-pitch-mechanics.ts:419` (MetallosisPoisonAbAttr.gate), after the inherited damaging-move test.
- Slots: `other` (the target I hit); WHEN `event.after-my-hit`. For defending triggers the equivalent reads the holder's own record.
- Needed by: MetallosisPoisonAbAttr (Metallosis). Its gate is legacy until this exists.

## Guards (safety rules, non-removable)

### R6. `hit-dealt-damage` (proposed): "Only triggers when the hit really dealt damage"
- Formula: `damage > 0`, with the frame's `damage` slot.
- Source: `fakemon-pitch-mechanics.ts` MoxibustionAbAttr.guards and MetallosisPoisonAbAttr.guards (both are `damage > 0`; before this change they were the second clause of canApply).
- Slots: `damage` (WHEN `event.after-my-hit` provides it).
- Needed by: MoxibustionAbAttr, MetallosisPoisonAbAttr. Today written as feasibility text in the declarations.

### R8. Guards for the knock-out reaction (proposed ids `knocked-out-by-a-move`, `attacker-known`, `attacker-still-standing`)
- Formulas, in the original order: `!!move`; `!!attacker`; `!attacker.isFainted()`.
- Source: `bernerd-roster-mechanics.ts` MutualDestructionPostFaintAbAttr.guards (clauses 1 to 3 of the old canApply).
- Slots: `move`, `other` (WHEN `event.faint` provides them). A single combined guard is acceptable if the librarian prefers.
- Needed by: MutualDestructionPostFaintAbAttr. Today written as feasibility text.

## Effects (DO)

### R2. `effect.survive-lethal-hit` (proposed): "Survive a knockout hit with 1 HP"
- Formula: unless simulated, `holder.addTag(BattlerTagType.STURDY, 1)` (the damage pipeline reads the tag and leaves 1 HP); the once-per-turn rule comes from the tag being present.
- Source: `ab-attrs.ts:344` (PreDefendFullHpEndureAbAttr.apply), reused by `pre-faint-revive.ts` (PreFaintReviveAbAttr, B11).
- Slots: `holder`, `damage`, `simulated`; WHEN `calc.damage-taken` (dispatch key `PreDefendFullHpEndureAbAttr`).
- Needed by: LingeringMuskEndureAbAttr (together with a marker, see R9). The class stays a package until this and R1 exist.

### R4. `effect.faint-self` (proposed): "Make myself faint"
- Formula: unless simulated, `holder.damageAndUpdate(holder.hp, { result: HitResult.INDIRECT })`.
- Source: `bernerd-roster-mechanics.ts:234-240` (LingeringMuskPostTurnAbAttr.apply).
- Slots: `holder`, `simulated`.
- Needed by: LingeringMuskPostTurnAbAttr.

### R7. `effect.faint-other` (proposed): "Make the other Pokemon faint"
- Formula: unless simulated, `other.damageAndUpdate(other.hp, { result: HitResult.INDIRECT })` (all of its current HP).
- Source: `bernerd-roster-mechanics.ts` MutualDestructionPostFaintAbAttr.apply.
- Slots: `other`, `simulated`.
- Needed by: MutualDestructionPostFaintAbAttr.

### R9. `effect.set-marker` and `effect.tick-marker` (proposed): "Start a timed marker for N turns" and "Count a timed marker down by one turn"
- `set-marker` params: `scope`, `key`, `turns`. Formula for Oracle: `battleData.erAbilityProvenance.push("oracle:first-entry")`, then drop every `summonData` entry starting with `oracle:guard:`, then push `oracle:guard:${turns}` (the first-entry write is a separate `set-marker` with no turns). Source: `fakemon-pitch-mechanics.ts:654-661` (OracleEntryAbAttr.apply).
- `tick-marker` formula: find the entry starting with `oracle:guard:`, `turns = Number(suffix)`, remove it, push `oracle:guard:${turns - 1}` while `turns > 1`. Source: `fakemon-pitch-mechanics.ts:675-690` (OracleGuardTickAbAttr.apply).
- A matching atom for "a timed marker is running" is part of R3 (`match: "prefix"`).
- Needed by: OracleEntryAbAttr, OracleGuardTickAbAttr; also LingeringMuskEndureAbAttr's marker write if the marker moves into the provenance memory.

## Other notes for the librarian

- `effect.drain` ("Heal {percent}% of the damage dealt") is used by MoxibustionAbAttr as its declared effect. The class heals `max(1, floor(damage * share))` through a `PokemonHealPhase`; the effect formula should say "at least 1 HP" and "floor".
- `effect.steal-item` ("Steal {target}'s item") is used by ErMagicianStealAbAttr as its declared effect. The actual rule steals ONE RANDOM transferable item (`randBattleSeedInt` over the transferable items, only when one exists and `canTransferHeldItemModifier` allows it) and shows a message; the effect's description should say "one random item that can be taken".

# Chunk 2 of B17 (PentaPunchFuryPowerAbAttr, PerpetualMotionTriggerAbAttr, PerpetualMotionPostTurnAbAttr, PerpetualMotionResolutionAbAttr, PhoenixFoliageUseFormChangeAbAttr, PhoenixFoliageHitFormChangeAbAttr, ErTransmuteOpposingBerriesAbAttr, ClearOpponentStatBuffsOnSummonAbAttr)

Numbering continues from chunk 1. Ids marked "proposed" are suggestions; the librarian may rename them but must keep the formula.

## Conditions (atoms)

### R10. `move.is-move` must accept Elite Redux moves (change to an existing atom)
- Formula: `move.id === (MoveId[moveId] ?? ErMoveId[moveId])`. Today `evaluate/conditions.ts:228` calls `enumValue(MoveId, moveId, "move")`, which throws for a name that only exists in `ErMoveId` (for example `FIVE_STAR_FURY`, `src/enums/er-move-id.ts:170`).
- Source: `fakemon-pitch-mechanics.ts` `PentaPunchFuryPowerAbAttr.gate` (`move.id === ErMoveId.FIVE_STAR_FURY`); the same test is the closure of Penta-Punch's `ChangeMovePriorityAbAttr` (attr 2) and the filter of its `CritStageBonusAbAttr` (attr 3).
- Slots: `move` (WHEN `calc.move-power` provides it). The param list in the editor must offer the Elite Redux move names too.
- Needed by: PentaPunchFuryPowerAbAttr (gate is legacy until this exists); also the two sibling attrs of Penta-Punch in other batches.

### R12. `hit.landed` (proposed): "My hit really landed"
- Formula: `hitResult` is one of `EFFECTIVE`, `SUPER_EFFECTIVE`, `NOT_VERY_EFFECTIVE`, `ONE_HIT_KO` (so not a miss, not "no effect", not a failure, not a status or indirect result).
- Source: `fakemon-pitch-mechanics.ts` `PERPETUAL_MOTION_SUCCESSFUL_HITS` and `PerpetualMotionTriggerAbAttr.gate` clause 2 (also read by `PerpetualMotionProgressAbAttr.apply`, B14).
- Slots: `hitResult` (WHEN `event.after-my-hit` provides it; the frame already carries it as `frame.hitResult`).
- Needed by: PerpetualMotionTriggerAbAttr (its gate is legacy until R12 and R13 exist).

### R13. `move.is-queued-follow-up` (proposed, param `key`): "The move is the follow-up this ability queued"
- Formula: `move.attrs.some(attr => attr instanceof ScriptedMoveMarkerAttr && attr.key === key)`; the shipped key is `"perpetual-motion"`.
- Source: `fakemon-pitch-mechanics.ts` `PerpetualMotionTriggerAbAttr.gate` clause 3 (used negated); the same test is in `PerpetualMotionProgressAbAttr.canApply` and `PerpetualMotionPowerAbAttr.canApply` (B14) and Astral Project / Splash Damage style markers use the same attr class (`archetypes/scripted-move-util.ts:96`).
- Slots: `move`.
- Needed by: PerpetualMotionTriggerAbAttr.

### R17. `time.last-move-result` and `time.last-move-was-follow-up` (proposed)
- Formulas: `pokemon.getLastXMoves(1)[0]?.result === MoveResult[result]` (with a "is not" option for `SUCCESS`), and `pokemon.getLastXMoves(1)[0]?.useMode === MoveUseMode.INDIRECT`.
- Source: `fakemon-pitch-mechanics.ts` `PerpetualMotionResolutionAbAttr.residual` (`move?.useMode === MoveUseMode.INDIRECT && move.result !== MoveResult.SUCCESS`). Together with the chain flag of R16 these would let the residual be promoted into the gate.
- Needed by: PerpetualMotionResolutionAbAttr (today kept as written feasibility, the gate itself already maps to `time.last-move`).

## Guards (safety rules, non-removable)

### R18. `after-my-final-hit` (proposed): "Only triggers after the final hit of my own multi-hit move"
- Formula: `!(holder.turnData.hitsLeft > 1)` (the holder is the attacker for the "after my attack" trigger).
- Source: `fakemon-pitch-mechanics.ts` `PhoenixFoliageUseFormChangeAbAttr.guards` clause 2 (`params.pokemon.turnData.hitsLeft <= 1`).
- Slots: `holder`. Note for the librarian: the existing guard `after-final-hit` reads `other.turnData.hitsLeft` (the attacker, written for a defending trigger). Generalising it to "the attacker's hits left" (holder for my own attack, other for being hit) would serve both; I may not edit the guard registry.
- Needed by: PhoenixFoliageUseFormChangeAbAttr (today written as feasibility text; the class keeps the check in its `guards` method).

## Harness (for the harness owner, B20)

### R22. L1 engine-parameter builder for `event.my-move-starts` (dispatch key `ExecutedMoveAbAttr`)
- What is missing: `PARAM_BUILDERS` in `test/tests/elite-redux/decomp/harness/world.ts` has no entry for `event.my-move-starts`, so the L1 attr differential refuses ("add an engine-parameter builder for its trigger") any Tier B class of that trigger whose gate is bound. The params are `{ pokemon: holder, simulated: false }` (AbAttrBaseParams), like `event.end-of-turn`.
- A second gap: `PerpetualMotionResolutionAbAttr` keeps its gate in `apply` (through `gatedCanApply`), because the inherited `canApply` is always true and the ability flyout is queued at every move of mine (apply-ab-attrs.ts). L1 compares `canApply` of the original and the rebuilt attr, which is `true` for both, so it cannot see the gate. The differential would have to call `apply` on a state where the holder's last move is Rollout (and where it is not) and compare the written chain state.
- Needed by: PerpetualMotionResolutionAbAttr. Its gate (atom `time.last-move`, holder, ROLLOUT) is proved by hand in `test/tests/elite-redux/decomp/B17/penta-perpetual.test.ts` meanwhile, and the binding is a written legacy-closure until this exists.
