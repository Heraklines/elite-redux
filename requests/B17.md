# Library requests from batch B17 (for the librarian, B19)

Plain list, not code. Each entry says what is needed, the exact formula and source, and which class needs it.
Chunk 1 of B17 (LingeringMuskEndureAbAttr, LingeringMuskPostTurnAbAttr, ErMagicianStealAbAttr, MetallosisPoisonAbAttr,
MoxibustionAbAttr, MutualDestructionPostFaintAbAttr, OracleEntryAbAttr, OracleGuardTickAbAttr). Later chunks append below.

Ids marked "proposed" are suggestions; the librarian may rename them but must keep the formula.

## Conditions (atoms)

### R1. `hit.would-knock-out` (proposed): "The hit would knock me out"
- Formula: `damage >= holder.hp` (the frame's effective damage against my current HP).
- Source: `src/data/elite-redux/archetypes/pre-faint-revive.ts:171` (`if (damage.value < pokemon.hp) return false`) and `ab-attrs.ts:339` (`damage.value >= pokemon.hp`).
- Slots: `holder`, `damage` (WHEN `calc.damage-taken` provides them).
- Needed by: LingeringMuskEndureAbAttr (Lingering Musk). Also the inherited rule of PreFaintReviveAbAttr (B11) and Sturdy.
- Note for B11 / the librarian: the clauses of `PreFaintReviveAbAttr.canApply` (HP gate, max HP above 1, the knockout test, the once-per-turn marker) would have to be split into guards / gate / residual in that class so that its subclasses can expose them; I may not edit that file.

### R3. `time.marker-set` (proposed): "A marker is set on me" (memory flag)
- Formula: reads the ER provenance memory of a scope: `scopeData.erAbilityProvenance.includes(key)` for `match: "exact"`, `scopeData.erAbilityProvenance.some(v => v.startsWith(key))` for `match: "prefix"`.
- Params: `scope` (`battle` = `pokemon.battleData`, `switch-in` = `pokemon.summonData`, `turn` = `pokemon.turnData`), `key` (text), `match` (exact or prefix). Pure; never writes.
- Sources: `fakemon-pitch-mechanics.ts:630` OracleEntryAbAttr gate (`!battleData.erAbilityProvenance.includes("oracle:first-entry")`, used negated), `:664` OracleGuardTickAbAttr gate (`summonData.erAbilityProvenance.some(v => v.startsWith("oracle:guard:"))`).
- The same atom is needed for the marker of Lingering Musk, which today is a loose field: `bernerd-roster-mechanics.ts:233` reads `tempSummonData.lingeringMuskFaint`. Either the atom also accepts a named flag on `tempSummonData`, or B14 moves it into the provenance memory later (a separate behaviour-neutral change for the owner to decide).
- Needed by: LingeringMuskPostTurnAbAttr, OracleEntryAbAttr, OracleGuardTickAbAttr. Many other ER classes keep markers in this same memory (Eulogy, Splash Damage, Somniloquy, Booby Trap, Celestial Jelly), so the atom pays off beyond this batch.
- Today these three gates are written as legacy-closure, so those three attrs cannot be rebuilt from the library (status legacy-closure-pending-request).

### R5. `hit.was-critical` (proposed): "The hit was a critical hit"
- Formula: `!!other.turnData.attacksReceived[0]?.critical` (index 0 is the NEWEST record; `move-effect-phase.ts:989` unshifts).
- Source: `fakemon-pitch-mechanics.ts:419` (MetallosisPoisonAbAttr.gate), after the inherited damaging-move test.
- Slots: `other` (the target I hit); WHEN `event.after-my-hit`. For defending triggers the equivalent reads the holder's own record.
- Needed by: MetallosisPoisonAbAttr (Metallosis). Its gate is legacy until this exists.

## Effects (DO)

### R9. `effect.set-marker` and `effect.tick-marker` (proposed): "Start a timed marker for N turns" and "Count a timed marker down by one turn"
- `set-marker` params: `scope`, `key`, `turns`. - Needed by: OracleEntryAbAttr, OracleGuardTickAbAttr; also LingeringMuskEndureAbAttr's marker write if the marker moves into the provenance memory.

## Other notes for the librarian

- `effect.drain` ("Heal {percent}% of the damage dealt") is used by MoxibustionAbAttr as its declared effect. The class heals `max(1, floor(damage * share))` through a `PokemonHealPhase`; the effect formula should say "at least 1 HP" and "floor".
- `effect.steal-item` ("Steal {target}'s item") is used by ErMagicianStealAbAttr as its declared effect. The actual rule steals ONE RANDOM transferable item (`randBattleSeedInt` over the transferable items, only when one exists and `canTransferHeldItemModifier` allows it) and shows a message; the effect's description should say "one random item that can be taken".
