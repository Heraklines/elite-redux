## Conditions (IF atoms) and guards

### R-B18-1  `calc.speed-bypass` should provide `simulated`, and a guard `not-while-previewing`  (ProvenanceBypassSpeedChanceAbAttr)

- The class's first clause is `!simulated` (`bypass-speed-provenance.ts`, `guards`): the turn-order preview never rolls the

  (`ab-attrs.ts:7022`); it must provide `simulated` too, otherwise the guard cannot be declared.

### R-B18-3  `move.chosen-is-damaging`  (ProvenanceBypassSpeedChanceAbAttr residual)

- Label: "The move I chose this turn deals damage". Group "Move". Requires `holder`. Pure.
- Formula: `const cmd = globalScene.currentBattle.turnCommands[holder.getBattlerIndex()]; const m = cmd?.move?.move ? allMoves[cmd.move.move] : null; m?.category === PHYSICAL || m?.category === SPECIAL`
  (`bypass-speed-provenance.ts` `residual`, copied from `ab-attrs.ts:7025-7027`). Note it reads the COMMAND chosen at the start of the
  turn, not a move being used, so the existing `move.damaging` (which needs the `move` slot) cannot replace it.
- With this atom the gate becomes `[rng.chance, move.chosen-is-damaging]` in that order (the roll stays first and is still drawn for
  a status move) and only `canAddTag(BYPASS_SPEED)` stays in the class as feasibility.

### R-B18-4  `mon.has-active-first-innate`  (PostDefendSuppressFirstInnateAbAttr residual)

## Conditions (IF atoms) and guards

### R-B18-23  atom `stat.is-highest` with a choice of whose stats  (HigherStatMultiplierAbAttr, AllyHigherStatMultiplierAbAttr)

- Label: "The stat is the highest of {stats} for {who}". Params `stats` (a list of Attack, Defense, Sp. Atk, Sp. Def, Speed in that fixed order) and `who`
  (me, my ally that receives the stat). Requires slot `stat`; for the ally dispatch also a slot for the receiving Pokemon (`target`), which `calc.stat-value`

- Formula (`requested-combat-riders.ts`, `gate`): `highest = stats[0]; for each other s: if (mon.getStat(s, false) > mon.getStat(highest, false)) highest = s;

  `mon` is the holder for HigherStatMultiplierAbAttr and `target` for AllyHigherStatMultiplierAbAttr.
- Needed by: Flower Gift (122 attrs 3, 4, 5, 6). Today their gate bindings are legacy-closure.

### R-B18-24  guard `not-already-blocked`  (ReverseNegativeStatChangesAbAttr)

### R-B18-25  atom `source.exists`: "The change has a source"  (ReverseNegativeStatChangesAbAttr, residual)

- Formula `source !== null` (`requested-combat-riders.ts`, `residual`). Mind the null versus undefined difference: the engine's parameter type says `source` is

  Until then the clause stays in the residual and is shown as "also requires". `cancel.stat-drop` provides `other`; the frame builder maps `source` to it, so
  `side.is` cannot tell "no source" from "foe".
- When this atom exists, move `source !== null` from `residual` into `gate` (a pure move).

### R-B18-27  atom `field.weather-active` with a list and the suppression test  (Flower Gift's attr-level condition)

- Label: "The weather is {weathers} and is not suppressed". Params `weathers` (a list). Formula:

### R-B18-29  `effect.multiply-stat` whose multiplier grows with a count  (FaintedAllyStatMultiplierAbAttr)
