# Requests from batch B18 (chunk 1 of 5) to the librarian (B19) and the harness owner (B20)

Not code. One entry per request: id, what it must do, the source line, and which class needs it. Chunk 1 owns
ProvenanceBypassSpeedChanceAbAttr, FirstTurnDirectDamageMultiplierAbAttr, BiomeRevealBonusAbAttr,
ExperienceGainMultiplierAbAttr, MoneyGainMultiplierAbAttr, BallRecoveryAbAttr, MoveHpCostModifierAbAttr and
PostDefendSuppressFirstInnateAbAttr.

## Edits made outside the batch's own files (minimal, so L0 and L1 pass; the captain keeps one copy of each)

### R-B18-0  marker classes as `while.active` flag keys, and a turn-order param builder

- `vocabulary/when-registry.ts`: `BallRecoveryAbAttr`, `BiomeRevealBonusAbAttr`, `ExperienceGainMultiplierAbAttr`,
  `MoneyGainMultiplierAbAttr`, `MoveHpCostModifierAbAttr` were added (alphabetically) to the `flagKeys` of `while.active`,
  and to `ER_MARKER_FLAG_KEYS` in `test/tests/elite-redux/decomp/l0-dispatch-keys.test.ts`. They extend `AbAttr` directly and
  are read by name (`erMetaKind` readers), so no WHEN lists them and L0 refuses "dispatches ..., none of which is the class
  or one of its ancestors". B13 made the same kind of edit for its marker classes (R-B13-19); merge both lists.
  Better long term: a WHEN "While the game works out my rewards or the map" (kind while-active) that names these readers.
- `test/tests/elite-redux/decomp/harness/world.ts`: a `calc.speed-bypass` entry in `PARAM_BUILDERS`
  (`{ pokemon: holder, simulated: false }`, exactly what `BypassSpeedChanceAbAttr` receives). Without it the L1 attr
  differential says "add an engine-parameter builder for its trigger" for Quick Draw and Minigun.

## Conditions (IF atoms) and guards

### R-B18-1  `calc.speed-bypass` should provide `simulated`, and a guard `not-while-previewing`  (ProvenanceBypassSpeedChanceAbAttr)

- The class's first clause is `!simulated` (`bypass-speed-provenance.ts`, `guards`): the turn-order preview never rolls the
  chance and never adds the jump. No registered guard says that, so the declaration has `guards: []` and the class keeps
  the clause (locked, never removable) in its own `guards` method.
- Wanted: guard id `not-while-previewing`, label "Nothing happens while the game is only previewing", requires `simulated`,
  formula `!params.simulated`. `calc.speed-bypass` provides only `holder` today although the engine call carries `simulated`
  (`ab-attrs.ts:7022`); it must provide `simulated` too, otherwise the guard cannot be declared.

### R-B18-3  `move.chosen-is-damaging`  (ProvenanceBypassSpeedChanceAbAttr residual)

- Label: "The move I chose this turn deals damage". Group "Move". Requires `holder`. Pure.
- Formula: `const cmd = globalScene.currentBattle.turnCommands[holder.getBattlerIndex()]; const m = cmd?.move?.move ? allMoves[cmd.move.move] : null; m?.category === PHYSICAL || m?.category === SPECIAL`
  (`bypass-speed-provenance.ts` `residual`, copied from `ab-attrs.ts:7025-7027`). Note it reads the COMMAND chosen at the start of the
  turn, not a move being used, so the existing `move.damaging` (which needs the `move` slot) cannot replace it.
- With this atom the gate becomes `[rng.chance, move.chosen-is-damaging]` in that order (the roll stays first and is still drawn for
  a status move) and only `canAddTag(BYPASS_SPEED)` stays in the class as feasibility.

### R-B18-4  `mon.has-active-first-innate`  (PostDefendSuppressFirstInnateAbAttr residual)

- Label: "{who} has an active first extra ability". Params `who` (holder, other). Pure.
- Formula: `pokemon.getActiveAbilitySources().some(source => source.passive && source.passiveSlot === 0)`
  (`mummy-family.ts:42`). With a `slot` param (first, second, third extra ability) it would also cover the other two slots.
- Then the residual can move into the gate as the last atom, in the original order (contact, not Mummy-style, has a first innate).

## Effects (DO blocks)

### R-B18-2  `effect.jump-turn-order`  (ProvenanceBypassSpeedChanceAbAttr apply)

- Label: "Move before others of the same priority this turn". Event effect. Requires `holder`. Param `memoName` (text, default
  `quick-draw:proc`, not shown to staff) because the effect also writes the per-turn memo.
- Formula: `pokemon.addTag(BattlerTagType.BYPASS_SPEED)` then `claimCommandAbilityProvenance(pokemon, memoName)`
  (`bypass-speed-provenance.ts` `apply`; the tag is `ab-attrs.ts:7040`, the memo `innate-slot-suppression.ts:105`).
  The memo is read by Quick Draw's own x2 power rider (`init-elite-redux-vanilla-rebalance.ts:633`), by Gunman
  (`init-elite-redux-ability-upgrades.ts:940`) and by the Pulse heal bonus (`data/moves/move.ts:3301`), so `effect.apply-tag`
  alone is not enough. Feasibility: `canAddTag(BYPASS_SPEED)`.

### R-B18-5  `effect.reveal-extra-biomes`  (BiomeRevealBonusAbAttr)

- Label: "Show extra biome choices on the world map". Param `count` (whole number 1 to 5, default 1). Group "Other".
- Formula: the sum over non-fainted party members of the `count` of each eligible attr
  (`archetypes/ability-meta-consumers.ts:83`, `getBiomeRevealBonus`, called by `er-biome-routing.ts`). It is a number a reader asks
  for, so the library effect is "contribute this number to that reader".

### R-B18-6  `effect.multiply-experience-gained`  (ExperienceGainMultiplierAbAttr)

- Label: "Multiply the experience I receive". Param `multiplier` (0.1 to 5, default 1.2). Group "Other".
- Formula: the product over the receiving Pokemon's eligible attrs (`ability-meta-consumers.ts:107`,
  `getExperienceGainMultiplier`, called by `phases/exp-phase.ts:33` and `phases/show-party-exp-bar-phase.ts:26`).

### R-B18-7  `effect.multiply-prize-money`  (MoneyGainMultiplierAbAttr)

- Label: "Multiply the prize money after a battle". Param `multiplier` (0.1 to 5, default 1.2). Group "Other".
- Formula: the product over the non-fainted Pokemon on the player's field, captured at battle end
  (`ability-meta-consumers.ts:115`, `getBattleMoneyGainMultiplier`; `snapshotBattleMoneyGainMultiplier` at `phases/battle-end-phase.ts:236`,
  read by `phases/money-reward-phase.ts:38`).

### R-B18-8  `effect.return-used-balls`  (BallRecoveryAbAttr)

- Label: "Get back used balls after a battle". Param `balls` (a list of ball kinds, at least one, default Poke Ball and Great Ball).
- Formula: for every ball kind named by any eligible attr of any party member (fainted included) move the number of balls used
  this battle back to the bag, once per physical ball (`ability-meta-consumers.ts:155`, `recoverUsedPokeballsAfterBattle`).

### R-B18-9  `effect.change-move-hp-cost`  (MoveHpCostModifierAbAttr)

- Label: "Change how much HP a substitute move costs me". Params `moves` (list, only Substitute and Shed Tail are read) and `fraction`
  (0.01 to 1, default one third). Group "Moves".
- Formula: replace the base fraction by `fraction` for a listed move; the last matching attr wins
  (`ability-upgrades/attrs/move-hp-cost.ts:32`, `getMoveHpCostFraction`, read by `AddSubstituteAttr.getHpCost`, `data/moves/move.ts:2745`).
  The reader never calls the attr's `getCondition`, so an IF on this effect would do nothing until that reader honours it.

### R-B18-10  `effect.disable-extra-ability`  (PostDefendSuppressFirstInnateAbAttr apply)

- Label: "Disable the attacker's extra ability until it switches out". Event effect. Requires `other` and `simulated`. Param `slot`
  (first, second or third extra ability, default first). Nothing happens when simulated.
- Formula: `suppressInnateSlotUntilSwitch(attacker, slot)` (`innate-slot-suppression.ts:21`, called with the literal slot 0 at
  `mummy-family.ts:48`). The class would have to take the slot as a constructor argument (default 0) for the param to be real;
  that class change is left for the owner of the effect because it touches the constructor.

## Conditions (IF atoms) and guards

### R-B18-11  slot `effectChance` and atom `move.effect-chance-between`  (IgnoreOptionalMoveEffectsAbAttr, UserFieldIgnoreOptionalMoveEffectsAbAttr)

- `calc.incoming-effect-chance` provides `holder, move` only, although the engine call carries `chance`, a NumberHolder with the move's
  effect chance after Serene Grace and similar changes (`move.ts:2060`, `:2067`). It must also provide a slot `effectChance` (the number).
- Atom label: "The move's extra effect is not guaranteed (chance above 0% and below 100%)". Group "Move". Requires `effectChance`. Pure.
  Params `above` (number, default 0) and `below` (number, default 100) so a staff member can say "chance below 50%".
- Formula: `chance.value > above && chance.value < below` (`ability-upgrades/attrs/optional-secondary-effect.ts:13`, `isOptionalEffectChance`).
- With it, the Aroma Veil gates (both halves) bind to this atom and stop being legacy closures.

### R-B18-13  a WHEN for the side-wide effect-chance dispatch  (UserFieldIgnoreOptionalMoveEffectsAbAttr)

- Today `calc.incoming-effect-chance` lists `UserFieldIgnoreMoveEffectsAbAttr` as an `alsoDispatchKeys` entry, so the holder-only dispatch
  (the move's target, `move.ts:2060`) and the side-wide dispatch (every Pokemon of the target's side including the target, `move.ts:2067`)
  are one WHEN. Wanted: a second WHEN "While the game calculates effect chance against me or my allies" (kind calc, same provides, dispatch key
  `UserFieldIgnoreMoveEffectsAbAttr`), so a staff rule can pick "me only" or "my whole side". Sand Cloak (B-other batch) uses the same dispatch.

### R-B18-20  guard `not-when-target-fainted`  (BreakScreensOnAttackAbAttr)

- Label: "Nothing happens when the target has already fainted". Requires `other`. Formula: `!!params.opponent && !params.opponent.isFainted()`
  (`requested-combat-riders.ts`, `guards`, moved from the old `canApply`). The class keeps the clause (locked, never removable) in its own `guards` method.

### R-B18-21  atom `move.has-property-itself`  (BreakScreensOnAttackAbAttr, low priority)

- `move.flag` calls `doesFlagEffectApply`, which also counts flags that abilities inject (Dance, Sound, Horn, Slicing). The class tests the move's
  OWN flag with `move.hasFlag(flag)` (`requested-combat-riders.ts`, `gate`). Both give the same answer for Punching, which nothing injects, so
  Precise Fist is identical, but a staff rule built from the class with an injected property would differ. Wanted: atom "The move itself has the
  {flag} property" calling `move.hasFlag(flag)`, params as `move.flag`.

### R-B18-17b  slot `other` = the first living foe on `event.on-entry`  (TelekineticStruggleOnEntryAbAttr)

- `event.on-entry` provides `holder, simulated`. The class picks `pokemon.getOpponents(false).find(foe => !foe.isFainted())`
  (`requested-combat-riders.ts`, `apply`); with `other` set to that foe, the four checks (not Psychic or Dark: `mon.has-type` with `who: other`;
  no Heavy Metal weight: needs an atom `mon.heavy-weight`; no super heavy ability: `mon.has-ability`) could become conditions instead of class feasibility.
  They cannot move into `canApply` in the class itself, because they run after the ability pop-up and a move would hide the pop-up for an immune foe.

## Effects (DO blocks)

### R-B18-12  `effect.ignore-secondary-effects`  (IgnoreOptionalMoveEffectsAbAttr, UserFieldIgnoreOptionalMoveEffectsAbAttr)

- Label: "Block the move's extra effect". Calc effect, modifies `effectChance`. Requires `effectChance`. No params.
- Formula: `chance.value = 0` (`ab-attrs.ts:1559` and `:1577`). It must run even when `simulated`, because it changes a number the move code asks for.
  `effect.negate` modifies `cancelled`, not the effect chance, so it cannot stand in.

### R-B18-14  `effect.heal-party-percent`  (FirstEntryPartyHealAbAttr)

- Label: "Heal every living, hurt party member by a share of its max HP". Params `percent` (0.25 to 100, step 0.25, default 10). Group "Healing".
- Formula: for each member of `pokemon.isPlayer() ? getPlayerParty() : getEnemyParty()` that is `!isFainted() && hp > 0 && !isFullHp()`: heal
  `toDmgValue(member.getMaxHp() * percent / 100)`; a member `isOnField() && isActive(true)` gets a queued `PokemonHealPhase(index, amount, null, true)`,
  any other member `heal(amount); updateInfo()` (`party-recovery.ts:20-30` and `:56-68`). Not simulated.

### R-B18-15  `effect.heal-holder-and-adjacent-allies` or a wider `effect.heal-percent`  (HolderAndAlliesRecoveryAbAttr)

- Either a new effect "Heal me and the allies next to me by a share of max HP" with `percent` (0.25 to 100, step 0.25, default 6.25), or `effect.heal-percent`
  gets a target "me and the allies next to me", a non-integer percent and an "only if hurt" filter (today: whole-number percent, targets holder / foe / whole side,
  no hurt filter).
- Formula: targets = `[holder, ...holder.getAdjacentAllies()].filter(m => !m.isFainted() && m.hp > 0 && !m.isFullHp())`, each gets
  `PokemonHealPhase(index, toDmgValue(maxHp * percent / 100), null, true)`; nothing when simulated (`party-recovery.ts:78-110`).

### R-B18-16  `effect.make-field-weak-to-type`  (FieldPoisonWeaknessOnEntryAbAttr)

- Label: "Make every Pokemon on the field weak to a type". Param `type` (a Pokemon type, default Poison). Group "Types and immunities".
- Formula: for every `globalScene.getField(true)` member set the per-summon mark that `Pokemon.getAttackTypeEffectiveness` reads
  (`erPoisonWeakness`, `pokemon.ts:4474`): a move of that type has `multiplier = max(2, multiplier)` when `multiplier > 0`. Today the type is fixed to Poison in the

### R-B18-17  `effect.force-struggle-next-turn`  (TelekineticStruggleOnEntryAbAttr)

  cleared by `turn-end-phase.ts:155`.

### R-B18-18  `effect.remove-field-effects`  (PreLeaveFieldRemoveLinkedTailwindAbAttr, BreakScreensOnAttackAbAttr)

- Label: "Remove field effects from a side". Params `tags` (list of field effects: Tailwind, Reflect, Light Screen, Aurora Veil, ...) and `side` (my side, the target's side).
  Group "Weather and terrain".
- Formula: `globalScene.arena.removeTagsOnSide(tags, side)` (`removeTagOnSide(TAILWIND, holder's side)` for the single-tag form); for the screens case the side is
  `opponent.isPlayer() ? PLAYER : ENEMY`, for the Tailwind case `pokemon.isPlayer() ? PLAYER : ENEMY` (`requested-combat-riders.ts`). Not simulated.
- Done in chunk 2 on the class side: `PreLeaveFieldRemoveLinkedTailwindAbAttr` takes the field effect as constructor argument 0 (default Tailwind) and
  `BreakScreensOnAttackAbAttr` takes the list as argument 1 (default Reflect, Light Screen, Aurora Veil), so both settings are real, typed params of the
  declarations. The library effect only has to expose the same two settings.
