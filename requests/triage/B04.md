## Disagreements with LIBRARY-DECISIONS.md

Numbers D1 to D10 are shared with `requests/triage/B03.md` (D1, D4, D6, D7, D9, D10 are there).

- **D2. `effect.clear-weather` answers B09-20 but is silently the wrong formula for B04.** Section 4 (line 115) plans
  `effect.clear-weather` from B09-20 (`EntryTailwindClearWeatherAbAttr`: clears only when the weather is NOT immutable,
  requests/B09.md:211-215), labelled "Clear the weather (extreme weather stays)" (effects-library.ts:369-378). B04 asked
  for an effect of the same id whose classes clear primal weather on purpose: `PostSummonClearWeatherAbAttr.apply` and
  `PreLeaveFieldClearWeatherAbAttr.apply` both call `trySetWeather(WeatherType.NONE)` (A:4021-4024, A:4214-4217), and
  `trySetWeather` lets NONE pass the immutable check (src/field/arena.ts:465-467); the class doc says so (A:4006-4013).
  Rebinding Cloud Nine or the primal weathers to the planned effect would keep Heavy Rain alive when Primordial Sea
  leaves. The B04 ask has no decision in LIBRARY-DECISIONS.
- **D3. The reason given for deferring `move.is-critical` (section 5, line 140) does not fit B04's case.** It says the
  engine only hands over `critMult`. For `calc.defensive-stat-pick` the engine hands over `defender` and `statHolder`, no
  `critMult` (P:5677-5682), and it dispatches `CritUseLowerDefensiveStatAbAttr` only when `isCritical` (P:5676). The
  real problem is that the same WHEN also claims `LowerDefensiveStatVsStatusedFoeAbAttr` (when-registry.ts:727), which
  is dispatched on every hit (P:5692-5699), so neither a relabel nor an atom is right for both keys. The fix is a WHEN
  split (the line-146 cluster), not frame-slot work.
- **D5. B19's own rule would have implemented `effect.negate`, `effect.block-crit` and `effect.set-damage-roll`.**
  effects-library.ts:10-12 and LIBRARY-DECISIONS section 4 say effects "whose formula is a plain edit of the frame value"
  are implemented (`effect.raise-crit-stage`: `critStage.value += stages`). These three are exactly that:
  `cancelled.value = true` (A:4331, A:4365 and every cancel class), `blockCrit.value = true`, and
  `rollMultiplier.value = rollPercent / 100` (A:4757). They stay `implemented: false` (effects.ts:113-145) with no
  decision, although `effect.negate` is the effect of 36 declarations (B01 6, B04 10, B05 5, B12 4, 11 more in eight other batches) and
  B04 asked twice (sections 7 and 12).
- **D8. The two V1 stand-ins of B04's switch-out classes are not the class formulas, and B04's asks about them have no
  decision.** `decl/B04/PreSwitchOutResetStatusAbAttr.decl.ts:44` names `effect.cure-status`; the V1 runner cures with
  `cureStatus` only when `status != null` (ability-studio-rule-effect-phase.ts:63-70), the class also clears Bleed,
  Frostbite and Fear and fires for an ailment-only Pokemon (A:4123-4135). `decl/B04/PreSwitchOutHealAbAttr.decl.ts:43`
  names `effect.heal-percent`; same arithmetic, but the V1 runner queues a PokemonHealPhase from inside an effect phase
  while the class heals in place before the switch (A:4147-4153). Section 4 discusses `effect.heal-percent` only for
  fractions (line 115).
- Agreed and re-checked: `cancel.self-stat-drop` / `cancel.partner-self-stat-drop` deferral (line 146), the
  `effect.apply-tag` turn-count deferral (line 148), `mon.fainted`, `mon.form-number` (B04's `mon.form-index`), player
  names (section 7).
