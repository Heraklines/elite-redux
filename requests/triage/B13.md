1. **R-B13-10 (`effect.drain-pp`), filed under "one-off effects (B13-10 to B13-56)".** It is not single-user. The same formula,
   `PokemonMove.usePp(n)` = `ppUsed = min(ppUsed + n, getMovePp())` (`data/moves/pokemon-move.ts:106-108`), is applied by:
   - FoulHarvest (NSM:336);
   - Spiteful's `PpReductionOnContactAbAttr` (`pp-reduction-on-contact.ts:137`, asked again as R-B15-25);
   - Ill Will's `OnFaintEffectAbAttr` `attacker-pp-drain` (`on-faint-effect.ts:549-550`, all PP).

   The three differ only in which move is picked.
2. **R-B13-15, listed in section 4 as a user of `effect.stat-stages`.** That planned block changes a fixed list of stats
   (voc/effects-library.ts:300-316). Anneal asks for ONE stat chosen by the incoming move's category (NSM:568), and
   `effect.stat-stages` cannot do that. The right answer is Rejected (single user): two rules with `move.category` and the existing
   `effect.stat-stage` express it.
3. **R-B13-17, filed under "single-mechanic memory".** The memory is the generic once-per-turn memory:
   `time.once-per{scope: turn}` uses the same `${wave}:${turn}` key (voc/evaluate/conditions.ts:199-200 vs NSM:106-108). The one
   difference is that the class writes even on a simulated call (NSM:694, 1645), while the library skips that write
   (voc/evaluate/conditions.ts:171). That makes it an owner decision, exactly like B08-26 in section 5 "Deferred", not a rejection.
4. **R-B13-24, aliased in section 5 to `effect.hurt-percent-of-max-hp` (as `effect.take-max-hp-percent-damage`) and listed under it
   in section 4.** The formulas differ:
   - Two-Faced recoil is `min(hp - 1, floor(maxHp * pct / 100))`. It never faints the holder and has no minimum of 1 (NSM:951).
   - The Rough Skin family the planned block describes is `toDmgValue(maxHp / ratio)`. It can be lethal and has a minimum of 1 (`ab-attrs.ts:1474`).

   Rebinding Two-Faced on the alias would let the recoil knock out the holder. Either the planned block gets a "never faint"
   setting, or R-B13-24 is Rejected (single user, which is my decision).
5. **R-B13-26 / R-B13-16 / R-B13-27, rejected as one-off.** Two of the requested counters are public facts with no private
   memory: the healthy bench count (NSM:1098-1101) and the weight-class difference (NSM:601-613). Three classes use them across
   three abilities: FanFavoritePower and FanFavoriteAccuracy (Fan Favorite), and HeavyweightPower (Heavyweight, Meteor Mass).
   Only the Porous and Setlist counters are private.
6. **R-B13-32 (`effect.trap-foes`), rejected as one-off.** This is the same block as R-B06-18 `effect.trap-foe`: 5 attrs of
   `ArenaTrapAbAttr` (Shadow Tag, Frenzied Phantom, Magnet Pull, Arena Trap, Salt Circle) plus Ring General. LIBRARY-DECISIONS has no
   decision for R-B06-18 either (no "trap" entry besides the `tag.trapped` alias).
7. **R-B13-38 has an unanswered implied effect.** `effect.use-weaker-defense` (B04, R-B08-40) is the same one-line formula in three
   classes (`ab-attrs.ts:4811-4813`, `:4843-4845`, `field/pokemon.ts:5686-5688`). It is not mentioned anywhere in LIBRARY-DECISIONS.
8. **R-B13-36, rejected as one-off.** It needs no new atom: filling the existing `hits` slot for `event.after-my-hit` from
   `holder.turnData` (voc/evaluate/frame.ts:131) makes `not move.multi-hit` exact. This is frame-slot work, like the deferred
   `accuracy` slot of R-B13-28.
9. **R-B13-56, listed among WHENs that need a NEW engine dispatch site.** The moment already has a dispatch,
   `event.foe-raised-stat` (`stat-stage-change-phase.ts:353`, same `canBeCopied` rule). What is missing is the boosted-foe param
   and the per-stat position, so the request is Deferred with a smaller change than a new dispatch site.
10. **R-B13-53, described as a one-off moment.** It is a three-user engine hook (`field/pokemon.ts:6659-6667`: Life Preserver, Eclipse
    Wing, Cracked Vessel). Its "leave me at 1 HP" half is the already planned `effect.survive-lethal-hit`.
11. **No decision at all for R-B13-1, R-B13-12, R-B13-13, R-B13-19 and R-B13-33.** Section 9 says the cluster rules cover them, but no
    cluster fits:
    - R-B13-12: a reach-probe matching bug (Harness);
    - R-B13-13: already done in code (Info);
    - R-B13-19: the flag keys are Implemented, the hazard WHEN is Rejected;
    - R-B13-33: harness work done, fixture stale;
    - R-B13-1: Rejected for the stated reason.
12. **R-B13-20 effect credited only to B09-31.** The planned `effect.multiply-accuracy-against-me` cannot simply be wired for Vapor
    Body on `calc.incoming-accuracy`. The engine applies Vapor Body after the attacker's `SetMoveAccuracyAbAttr` (`move.ts:1249`,
    `:1255`), while WonderSkin runs before it (`:1239`). The completion pass must not rebind it there.

The B13 rejections not listed above agree with LIBRARY-DECISIONS: memory atoms, by-name engine hooks and single-user effects.
