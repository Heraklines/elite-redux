## Disagreements with LIBRARY-DECISIONS.md

1. **R-B18-12 vs LIB section 4** ("`effect.multiply-effect-chance` ... For ... IgnoreMoveEffects (multiplier 0)"). Not the same formula. The library feasibility skips Order Up and Electro Shot (V/evaluate/effects.ts:131-146). `IgnoreMoveEffectsAbAttr` and `UserFieldIgnoreMoveEffectsAbAttr` only test `chance.value > 0` and then set it to 0 (ab-attrs.ts:1804-1810, 1822-1828). Both are dispatched at move.ts:2060/2067 for every move. So Shield Dust against Order Up or Electro Shot would change behaviour. It needs its own `effect.ignore-secondary-effects`.
2. **R-B18-24 is listed under "Rejected" in LIB section 5 (line 139)**, but the text says deferred. It is Deferred, because it needs a `cancelled` slot. It is not a rejection.
3. **LIB line 136 puts "B18" under the one-off single-ability rule.** That is wrong for R-B18-18, 23, 29 and 32 (each has 2 classes or 2+ abilities, or a twin request in B12) and for R-B18-1/2/3 (vanilla BypassSpeedChanceAbAttr shares them). These are Justified-unbuilt, not Rejected.
4. **LIB line 124 maps `move.has-property-itself` to `move.inherent-flag`.** This is correct (verified). But R-B18-31(a) is not covered: the `moveUser` slot on `calc.move-immunity` plus the second reader at pokemon.ts:4257 remain open.
5. **LIB never names R-B18-20, R-B18-30 or R-B18-33.** These are actually already satisfied by `attacker-still-standing`, `hp.crossed-below` `damage-value` and `mon.fainted` respectively. The completion pass should rebind them: OnceLowHpStatRaise residual to gate; OnDirectFaintRetaliation residual to the `attacker-still-standing` guard or `not mon.fainted{other}`; BreakScreens guard to `attacker-still-standing`.
6. **LIB line 117 lists `effect.faint-self` / `faint-other` as asked by B18.** No B18 entry asks for them. This is a misattribution only.
